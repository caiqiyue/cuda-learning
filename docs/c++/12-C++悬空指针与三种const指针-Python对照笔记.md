## 一、先复习：指针变量和它指向的对象是两份不同的东西

我们前面已经讨论过：

```cpp
int num = 10;
int* p = &num;
```

- `num`：一个 `int` 对象，保存整数 `10`。
- `p`：一个 `int*` 指针变量，保存 `num` 的地址。
- `&num`：取出 `num` 的地址。
- `p`：访问指针保存的地址。
- `*p`：沿着地址访问 `num` 这个对象。
- `&p`：取出**指针变量 `p` 自己**的地址。

### 1.1 我之前的疑问：`int* p = new int;` 是不是申请了两块空间？

```cpp
int* p = new int;
```

以当前常见的 **Windows x64 + MSYS2 G++** 环境为例，可以用下面的简化模型理解：

```text
局部指针变量 p                       动态创建的 int 对象
┌───────────────────┐               ┌───────────────────┐
│ 类型：int*        │ ────────────► │ 类型：int         │
│ 大小：通常 8 字节  │ 保存其地址     │ 大小：通常 4 字节  │
│ 值：假设 0x2000   │               │ 初始值：未确定    │
└───────────────────┘               └───────────────────┘
  自己也有地址，例如 0x1000           对象地址，例如 0x2000
```

**准确说法：**

1. `new int` 动态创建了一个 `int` 对象，并返回指向它的指针；这个 `int` 在该写法下**没有确定的初始值**。
2. 局部变量 `p` 保存这个地址；它**不是 `new` 申请出来的第二块动态内存**，通常具有自动存储期。
3. 指针变量大小与“它指向的是 `int` 还是 `double`”通常无关：在常见的 64 位程序中，普通对象指针通常为 8 字节。严格大小以 `sizeof` 为准。
4. 编译器优化时，局部指针不一定实际独占一块栈内存；图只是便于理解的抽象。

**重要：**`new int` 后不要直接读取 `*p`。若希望一开始就是 `0`，写成：

```cpp
int* p = new int{};  // 将 int 初始化为 0
*p = 10;             // 可以修改动态 int 对象

delete p;            // 释放 new int 创建的对象
p = nullptr;         // 避免继续保留失效地址
```

### 1.2 和 Python 对比

```python
name = [10, 20, 30]
other = name
```

Python 里 `name` 和 `other` 是绑定到同一个列表对象的两个名字。C++ 的 `int* p` 则是**显式保存地址的指针对象**，不能把 Python 的名字绑定和 C++ 指针完全画等号。

## 二、第二个疑问：`delete[] data` 后，为什么 `data` 还能赋值？

我们之前讨论的是数组扩容：

```cpp
int* data   = new int[3]{10, 20, 30};
int* bigger = new int[5]{10, 20, 30, 40, 50};

delete[] data;  // 释放旧数组
data = bigger;  // 让 data 保存新数组的地址
```

### 2.1 释放前

```text
data   ──► 旧数组 [10, 20, 30]
bigger ──► 新数组 [10, 20, 30, 40, 50]
```

这里有 **两个局部指针变量** `data`、`bigger`，也有 **两块分别通过 `new[]` 创建的动态数组**。

### 2.2 执行 `delete[] data;`

```text
data   ──► 旧数组 [已释放，不能再访问]    ← 悬空指针
bigger ──► 新数组 [10, 20, 30, 40, 50]
```

`delete[]` 结束的是**旧动态数组的对象生命周期并释放其存储**，**不是销毁指针变量 `data`**。此时 `data` 还处于自己的作用域内，但不能再借它访问旧数组。

### 2.3 执行 `data = bigger;`

```text
data   ──┐
          ├──► 新数组 [10, 20, 30, 40, 50]
bigger ──┘
```

这句只把 `bigger` 中保存的地址复制给 `data`：

- **没有新建第三个数组**；
- **没有把新数组元素再复制一遍**；
- `data` 和 `bigger` 此时指向的是**同一块新数组**。

你可以记住一个生活类比：**指针像一张记录仓库地址的纸，`delete[]` 拆的是仓库，不是这张纸；`data = bigger` 是把纸上的地址改成新仓库地址。**

**完整、安全的演示：**

```cpp
#include <iostream>

int main() {
    int* data = new int[3]{10, 20, 30};
    int* bigger = new int[5]{10, 20, 30, 40, 50};

    delete[] data;    // 只释放旧数组
    data = bigger;    // 指向新数组
    bigger = nullptr; // 明确只由 data 负责后续释放（可选的所有权约定）

    std::cout << data[4] << '\n'; // 50

    delete[] data;    // 新数组只释放一次
    data = nullptr;
}
```

> 不能在 `delete[] data` 后继续 `data[0]`；也不能在 `data`、`bigger` 指向同一新数组时对二者各执行一次 `delete[]`——那是重复释放。把变量设为 `nullptr` 只会清除**这个变量**保存的地址，不会自动清除其他别名指针。

## 三、悬空指针（Dangling Pointer）到底是什么？

**悬空指针：指针原本指向过某个对象，但该对象已经不存在（生命周期已结束），这个指针不再能用来访问原对象。**

最典型的例子：

```cpp
int* p = new int(10);
delete p;            // 动态 int 已销毁、存储被释放
// 现在 p 已悬空，不要再使用 *p
p = nullptr;         // 清除 p 保存的失效地址
```

即使旧地址的某些字节暂时没变，也不能因此认为旧对象仍有效：**内存中看似还留着“10”，不代表你有权访问它**。释放后的空间可能很快被其他分配复用。

### 3.1 三种经常混淆的状态

| 状态 | 示例 | 含义 | 能否解引用 |
|---|---|---|---|
| 未初始化指针 | `int* p;`（局部） | `p` 没有确定的指针值 | **不能** |
| 空指针 | `int* p = nullptr;` | 明确不指向对象 | **不能** |
| 悬空指针 | `delete p;` 之后仍保留旧指向 | 原对象已结束生命周期 | **不能** |
| 有效指针 | `int n = 10; int* p = &n;` | 指向还活着的对象 | 可以，前提是类型和访问权限正确 |

**纠正课程中容易产生的误解：**“`int* p;` 就指向了随机一块合法内存”并不准确。对于未初始化的普通局部指针，我们只知道它没有可安全使用的确定值，不能假定它指向某个有效对象。

### 3.2 `nullptr` 能解决所有悬空问题吗？

不能。它只能表达“这个指针现在不指向对象”，也不会自动管理内存。例如：

```cpp
int* p = new int(10);
int* q = p;

delete p;
p = nullptr;
// q 仍然悬空；p = nullptr 不会自动更改 q
```

悬空还可能由**返回局部变量地址**等原因造成：

```cpp
// 错误示意：不要这样编写函数
int* bad() {
    int local = 42;
    return &local; // 函数结束后 local 不再存在
}
```

不要运行或解引用这个返回的地址；这里仅展示错误模式。

## 四、进入本节重点：`const` 究竟限制什么？

我们刚学过指针有两个层次：

```text
指针变量 p  ──►  被指向对象 num
  └─ p 的值       └─ *p 的值
  （保存的地址）     （对象里的数值）
```

因此给指针加 `const`，可能限制的是两个不同的东西：

1. **指针所保存的地址，能不能改？** → 能否 `p = &num2;`
2. **能否通过这个指针改被指向的值？** → 能否 `*p = 20;`

图片讲的三个类型，正好由这两个维度组合而成。

## 五、第一种：指向 `const` 的指针（Pointer to const）

```cpp
const int* p = &num1;
// 或写成：int const* p = &num1;
```

课程称为“指向常量的指针”，为了避免误解，更精确地叫：**指向 `const int` 的指针**。

```cpp
int num1 = 10;
int num2 = 100;
const int* p = &num1;

// *p = 20;     // 编译错误：不能通过 p 修改 num1
p = &num2;      // 正确：p 可以改为指向 num2
```

**两个结论：**

- ✅ `p = &num2`：可以改变指向。
- ❌ `*p = 20`：不能通过 `p` 修改所指向的值。

**最重要的精确补充：**这不一定代表 `num1` 本身永远不能改！

```cpp
int num1 = 10;
const int* p = &num1;
num1 = 30;       // 合法：num1 本身并不是 const
// *p = 30;      // 不合法：不能通过 p 改它
```

也就是说，这里的 `const` 主要约束**通过 `p` 进行的访问**。如果对象本来就是 `const int num1 = 10;`，则它本身才是不允许被修改的对象。

这跟你前面学过的 `const char* s = "itcast"; s = "777";` 是同一套规则：**允许重新指向，不能通过该指针改字符内容**。

---

## 六、第二种：`const` 指针（Const pointer）

```cpp
int* const p = &num1;
```

这一次 `const` 放在 `*` 后面，限制的是**指针变量 `p` 本身保存的地址**。

```cpp
int num1 = 10;
int num2 = 100;
int* const p = &num1;

*p = 20;        // 正确：通过 p 修改 num1
// p = &num2;   // 编译错误：p 自己不能改指向
```

**两个结论：**

- ❌ `p = &num2`：不允许改变指向。
- ✅ `*p = 20`：被指向的可修改 `int` 可以通过 `p` 修改。

由于指针变量本身不能再赋新地址，**定义它时就必须初始化**：

```cpp
// int* const p; // 错误：const 指针没有初始化
```

注意：`int* const p` 不是说它指向的对象永远存在。被指对象仍然可能提前结束生命周期，届时这个 `p` 一样可能成为悬空指针。

---

## 七、第三种：指向 `const` 的 `const` 指针（Const pointer to const）

```cpp
const int* const p = &num1;
```

这次两个限制同时存在：

```cpp
int num1 = 10;
int num2 = 100;
const int* const p = &num1;

// *p = 20;    // 编译错误：不能通过 p 改值
// p = &num2;  // 编译错误：不能改变 p 的指向
```

**两个结论：**

- ❌ 不能通过 `p` 修改值。
- ❌ 不能改变 `p` 保存的地址。

同样注意：如果 `num1` 本身不是 `const`，其他合法途径仍可能修改它；这两个 `const` 只是分别约束 `p` 的指向与通过 `p` 的写访问。

---

## 八、三种 `const` 指针对照表（本节最重要）

假设：

```cpp
int num1 = 10;
int num2 = 100;
```

| 声明方式 | `p = &num2` 改指向 | `*p = 20` 通过 p 改值 | 记忆方式 |
|---|:---:|:---:|---|
| `const int* p = &num1;` | ✅ | ❌ | **指向可变，读写权限受限** |
| `int* const p = &num1;` | ❌ | ✅ | **指向固定，数值可改** |
| `const int* const p = &num1;` | ❌ | ❌ | **指向固定，通过它不可改值** |

### 8.1 如何快速读懂 `const` 的位置？

一个好用的入门记法：

- `const int* p`：`const` 修饰 `int` —— **不能通过 `p` 改 `int`**。
- `int* const p`：`const` 修饰指针 `p` —— **`p` 不能换地址**。
- `const int* const p`：两边都有限制。

也可以从变量名向外读：

```text
const int * p         ：p 是指针，指向 const int
int * const p         ：p 是 const 指针，指向 int
const int * const p   ：p 是 const 指针，指向 const int
```

> 课程截图使用了“指向常量的指针”“常量指针”“指向常量的常量指针”三个名称。术语在不同教材里可能有歧义；写代码时**以完整声明形式和上表两种操作能否执行为准**。

## 九、`const` 和 `new/delete` 有什么关系？

截图提到了“需要常量，同时也需要动态内存分配”的场景。需要区分两个独立维度：

- `const`：决定哪些修改操作被允许。
- `new/delete`：控制某些对象的动态创建与销毁。

**`const` 不等于动态分配；动态分配也不必须使用 `const`。**

例如：

```cpp
const int fixed = 10;            // 普通 const 对象，无需 new
const int* p = &fixed;           // 指向 const 对象

const int* q = new const int(42); // 动态创建 const int
std::cout << *q << '\n';         // 可以读取
delete q;                        // 仍须释放动态对象
q = nullptr;
```

如果使用 `new` 手动管理资源，**`const` 不能防止内存泄漏、重复释放或悬空**。现代 C++ 更常使用 `std::vector`、`std::unique_ptr` 等工具来自动管理动态资源。

## 十、结合 Python 来理解

Python 最接近的直觉是“名字可以重新绑定对象”，但不是 C++ 指针的精确等价物：

```python
a = [10]
b = a
b[0] = 20       # 修改同一个列表
b = [100]       # 让名字 b 重新绑定另一个列表
```

C++ 指针则把“保存地址”和“通过地址修改对象”这两种操作明确分开：

```cpp
int num1 = 10;
int num2 = 100;
int* p = &num1;

*p = 20;       // 修改 num1 的数值
p = &num2;     // 修改 p 保存的地址
```

而三种 `const` 指针，就是对上述两种操作分别加上编译期约束。

**不要把 C++ `const` 直接理解成 Python 中的“绝对不可变对象”：**`const int*` 不保证原始 `int` 对象无法从其他地方修改。

## 十一、可以在 VS Code 运行的综合实验

以下代码在 C++17 下可编译，注释掉的错误语句**不要解除注释**，除非是为了有意观察编译报错。

```cpp
#include <iostream>

int main() {
    int num1 = 10;
    int num2 = 100;

    // 1. 指向 const 的指针：可以换地址，不能通过 p1 改值
    const int* p1 = &num1;
    p1 = &num2;
    // *p1 = 20;  // 编译错误
    std::cout << "p1 -> " << *p1 << '\n'; // 100

    // 2. const 指针：不能换地址，可以通过 p2 改值
    int* const p2 = &num1;
    *p2 = 20;
    // p2 = &num2; // 编译错误
    std::cout << "num1 = " << num1 << '\n'; // 20

    // 3. 双 const：不能换地址，也不能通过 p3 改值
    const int* const p3 = &num1;
    // *p3 = 30;   // 编译错误
    // p3 = &num2; // 编译错误
    std::cout << "p3 -> " << *p3 << '\n'; // 20

    // 4. 动态对象与指针的生命周期是两回事
    int* dynamic_p = new int(42);
    std::cout << "dynamic = " << *dynamic_p << '\n';
    delete dynamic_p;
    dynamic_p = nullptr;
    std::cout << "is null = " << (dynamic_p == nullptr) << '\n';

    return 0;
}
```

**预期输出：**

```text
p1 -> 100
num1 = 20
p3 -> 20
dynamic = 42
is null = 1
```

在 Windows PowerShell 中，例如当前文件名为 `pointer_const.cpp`：

```powershell
g++ -std=c++17 -Wall -Wextra -g -O0 .\pointer_const.cpp -o .\pointer_const.exe
.\pointer_const.exe
```

## 十二、5 个判断题（先做再看答案）

假设 `int a = 10, b = 20;`：

1. `const int* p = &a; p = &b;` —— 合法吗？
2. `const int* p = &a; *p = 30;` —— 合法吗？
3. `int* const p = &a; *p = 30;` —— 合法吗？
4. `int* const p = &a; p = &b;` —— 合法吗？
5. `int* p = new int(10); delete p; p = nullptr;` —— 合法吗？

<details>
<summary>参考答案（展开查看）</summary>

1. ✅ 合法：`p` 可以更改指向。
2. ❌ 不合法：不能通过 `p` 修改值。
3. ✅ 合法：`p` 的指向固定，但可通过它修改 `a`。
4. ❌ 不合法：`p` 是 const 指针，地址不能改。
5. ✅ 合法：释放动态对象后，将指针清空是正确做法。

</details>

## 十三、最后总结：这一节只记住 4 句话

1. **指针变量与它指向的对象是两个不同对象**，有各自的类型、存储位置和生命周期。
2. **`delete` / `delete[]` 删除的是通过 `new` / `new[]` 创建的动态对象**，不是自动销毁保存地址的局部指针变量。
3. **悬空指针指向的原对象已不存在，不能再解引用**；用 `nullptr` 可以清除某个指针的失效地址，但不会自动清除所有别名。
4. **`const int*` 限制通过指针修改数据；`int* const` 限制指针改地址；`const int* const` 两种都限制。**
