# C++ 多文件编程与编译流程

## 一、为什么需要多个文件？

小程序可以把所有代码写在一个 `.cpp` 文件中：

```
#include <iostream>

int main()
{
    std::cout << "Hello\n";
}
```

但大型项目通常包含很多功能：

* 用户界面
* 文件读写
* 数学计算
* 网络通信
* 模型推理
* 数据结构

如果全部写在一个文件中，会导致代码难以阅读和维护。因此通常会把程序拆分成多个文件。

C++ 中常见的文件类型：


| 文件        | 作用             |
| ----------- | ---------------- |
| `.h`/`.hpp` | 头文件，放声明   |
| `.cpp`      | 源文件，放实现   |
| `.o`/`.obj` | 编译后的目标文件 |
| `.exe`      | 最终可执行程序   |

---

## 二、声明与定义

### 1. 函数声明

函数声明只告诉编译器：

* 函数叫什么
* 返回什么类型
* 接收什么参数

```
int add(int a, int b);
```

这句话没有函数体，所以它是声明。

### 2. 函数定义

函数定义才是真正写出函数如何工作：

```
int add(int a, int b)
{
    return a + b;
}
```

函数定义同时也包含了声明信息。

## 三、一个简单的多文件程序

假设我们要实现加法函数。

### `my_func.h`

```
#ifndef MY_FUNC_H
#define MY_FUNC_H

int add(int a, int b);

#endif
```

这里放函数声明。

### `my_func.cpp`

```
#include "my_func.h"

int add(int a, int b)
{
    return a + b;
}
```

这里放函数实现。

### `main.cpp`

```
#include <iostream>
#include "my_func.h"

int main()
{
    int result = add(1, 2);

    std::cout << "result = " << result << '\n';

    return 0;
}
```

这里包含头文件，然后调用函数。

### 编译

三个文件要一起编译：

```
g++ main.cpp my_func.cpp -o app
```

运行：

```
./app
```

Windows 下通常是：

```
.\app.exe
```

注意：

```
g++ main.cpp -o app
```

只编译 `main.cpp`，没有把 `my_func.cpp` 加入编译过程，可能出现链接错误：

```
undefined reference to `add(int, int)`
```

因为编译器知道 `add` 的声明，却没有找到它的实现。

## 四、头文件为什么要有防重复包含？

一个头文件可能被多个文件间接包含。

例如：

```
#include "a.h"
#include "b.h"
```

而 `b.h` 内部又包含了 `a.h`。

这样 `a.h` 可能被包含两次，导致重复声明或重复定义。

常见写法是：

```
#ifndef MY_FUNC_H
#define MY_FUNC_H

int add(int a, int b);

#endif
```

含义是：

1. 如果没有定义 `MY_FUNC_H`
2. 就定义它
3. 保留中间内容
4. 以后再次遇到时跳过

现代 C++ 也常见：

```
#pragma once

int add(int a, int b);
```

`#pragma once` 更简洁，但它属于编译器支持的非标准指令；\`#ifndef\` 方式兼容性更传统。

---

## 五、\`#include\` 到底做了什么？

例如：

```
#include "my_func.h"
```

它不是运行时调用，也不是把文件编译成一个独立程序。

预处理阶段会近似地把它替换成头文件内容：

```
int add(int a, int b);
```

所以 `main.cpp` 经过预处理后，编译器才能看到 `add` 的声明。

尖括号和双引号通常有搜索路径区别：

```
#include <iostream>
```

主要搜索系统或编译器配置的头文件目录。

```
#include "my_func.h"
```

通常优先搜索当前项目目录。

## 六、为什么必须有 `main()`？

对普通 C++ 可执行程序来说，必须有一个程序入口：

```
int main()
{
    return 0;
}
```

`main` 可以理解为：

> 操作系统启动程序后，程序开始执行的位置。

程序启动的大致过程是：

```
操作系统启动程序
        ↓
运行时环境初始化
        ↓
调用 main()
        ↓
执行 main 中的代码
        ↓
main 返回
        ↓
程序结束
```

`main` 不是普通意义上由你自己调用的函数。它由 C++ 运行时环境调用。

常见形式有：

```
int main()
{
    return 0;
}
```

或者：

```
int main(int argc, char* argv[])
{
    return 0;
}
```

其中：

* `argc` 表示命令行参数数量
* `argv` 保存命令行参数

例如运行：

```
app input.txt
```

程序可以通过 `argv` 读取 `input.txt`。

### 为什么不能有两个 `main()`？

一个可执行程序只能有一个入口。

如果这样编译：

```
// a.cpp
int main() {}

// b.cpp
int main() {}
```

就会发生重复定义错误，因为链接器不知道应该从哪个 `main` 开始。

但不同的可执行程序可以分别拥有自己的 `main`：

```
hello.cpp -> hello.exe
test.cpp  -> test.exe
```

只要它们不是被链接成同一个程序即可。

## 七、编译的四个阶段

完整流程可以理解为：

```
源代码
  ↓
预处理
  ↓
编译
  ↓
汇编
  ↓
链接
  ↓
可执行程序
```

### 1. 预处理

处理：

* `#include`
* `#define`
* `#if`
* `#ifdef`

命令：

```
g++ -E main.cpp -o main.i
```

`.i` 文件是预处理后的 C++ 代码。

### 2. 编译

把预处理后的 C++ 代码转换为汇编代码：

```
g++ -S main.cpp -o main.s
```

`.s` 文件是汇编代码。

### 3. 汇编

把汇编代码转换为目标文件：

```
g++ -c main.cpp -o main.o
```

`.o` 文件是机器码的一部分，但还不是完整程序。

### 4. 链接

把多个目标文件、库文件组合成最终程序：

```
g++ main.o my_func.o -o app
```

链接器会：

* 合并多个目标文件
* 找到函数的具体实现
* 连接标准库和其他库
* 解决函数和变量的引用关系

通常可以一步完成：

```
g++ main.cpp my_func.cpp -o app
```

`g++` 会自动完成预处理、编译、汇编和链接。

## 八、什么是宏？

宏是由预处理器处理的文本替换规则。

```
#define NUM 10
```

预处理时：

```
std::cout << NUM;
```

大致会变成：

```
std::cout << 10;
```

宏发生在真正编译之前，因此宏本身不是变量，也不是函数。

### 宏常量

```
#define PI 3.14159
```

使用：

```
double area = PI * r * r;
```

### 宏函数

```
#define SQUARE(x) ((x) * (x))
```

使用：

```
int result = SQUARE(5);
```

预处理器大致替换为：

```
int result = ((5) * (5));
```

宏函数容易产生问题：

```
#define SQUARE(x) x * x

int result = SQUARE(1 + 2);
```

替换后可能变成：

```
int result = 1 + 2 * 1 + 2;
```

结果不是预期的 `9`。

因此至少要加括号：

```
#define SQUARE(x) ((x) * (x))
```

不过现代 C++ 通常更推荐：

```
constexpr int square(int x)
{
    return x * x;
}
```

或者：

```
constexpr int num = 10;
```

它们比宏具有更好的类型检查和调试能力。

## 九、\`#define\` 的几种常见用途

### 1. 定义宏常量

```
#define BUFFER_SIZE 1024
```

### 2. 条件编译

```
#ifdef _WIN32
    // Windows 代码
#endif
```

```
#ifndef DEBUG
    // 没有定义 DEBUG 时编译
#endif
```

### 3. 头文件防重复包含

```
#ifndef MY_FUNC_H
#define MY_FUNC_H

// 头文件内容

#endif
```

### 4. 取消宏

```
#undef NUM
```

## 十、宏和变量的区别

```
#define NUM 10
```

这是文本替换。

```
const int num = 10;
```

这是有类型的常量对象。


| 对比             | 宏                  | 常量对象 |
| ---------------- | ------------------- | -------- |
| 处理时间         | 预处理阶段          | 编译阶段 |
| 是否有类型       | 没有                | 有       |
| 是否有作用域     | 基本没有 C++ 作用域 | 有       |
| 是否容易调试     | 较差                | 较好     |
| 是否进行类型检查 | 不进行              | 进行     |

日常 C++ 代码中，优先使用：

```
constexpr
const
inline
函数
```

宏主要用于条件编译、平台判断和头文件保护。

## 十一、头文件中应该放什么？

头文件通常放：

* 函数声明
* 类声明
* 结构体定义
* 枚举定义
* 常量声明
* 模板定义
* 必要的类型声明

例如：

```
#ifndef STUDENT_H
#define STUDENT_H

#include <string>

struct Student
{
    std::string name;
    int age;
};

void print_student(const Student& student);

#endif
```

源文件通常放：

* 函数实现
* 成员函数实现
* 具体业务逻辑

```
#include "student.h"
#include <iostream>

void print_student(const Student& student)
{
    std::cout << student.name << '\n';
}
```

## 十二、一个重要原则：不要在头文件中重复定义普通函数

错误示例：

```
// math.h
int add(int a, int b)
{
    return a + b;
}
```

如果多个 `.cpp` 文件都包含这个头文件，可能导致重复定义。

通常应该拆开：

```
// math.h
int add(int a, int b);
```

```
// math.cpp
int add(int a, int b)
{
    return a + b;
}
```

例外情况包括：

* `inline` 函数
* 模板
* 类内定义的成员函数
* `constexpr` 函数的某些写法

初学阶段可以先遵循：

> 头文件放声明，源文件放实现。

## 十三、整章知识图

```
多个源文件
    ↓
头文件保存声明
    ↓
cpp 文件保存实现
    ↓
main.cpp 包含头文件并调用
    ↓
预处理展开 include 和宏
    ↓
每个 cpp 分别编译
    ↓
链接器合并目标文件
    ↓
生成一个可执行程序
    ↓
操作系统调用 main()
```

最重要的对应关系是：

```
.h   -> 告诉别人有什么
.cpp  -> 写清楚具体怎么做
main -> 指定程序从哪里开始
宏   -> 预处理阶段进行文本或条件处理
链接 -> 把多个文件和库组合成程序
```

其中，“每个 `.cpp` 文件分别编译”是理解多文件编程的关键。\`main.cpp\` 不会自动获得其他 `.cpp` 文件中的函数实现；它需要通过头文件看到声明，并在最终链接时把对应的实现文件一起加入。
