## 二、先复习：指针变量保存的是“地址”

```cpp
int num = 10;
int* p = &num;
```

- `num`：一个 `int` 对象，保存整数 `10`。
- `&num`：获取 `num` 的地址。
- `p`：一个 `int*` 指针变量，保存 `num` 的地址。
- `*p`：根据 `p` 保存的地址，访问它所指向的 `int` 对象。
- `&p`：获取**指针变量 `p` 本身**的地址。

假设 `num` 位于 `0x1000`，`p` 自己位于 `0x2000`：

```text
地址 0x2000：指针对象 p ── 保存 0x1000 ──────┐
                                             │
地址 0x1000：整数对象 num ── 保存 10 ◀────────┘
```

| 表达式 | 在此示例中的含义 | 假设结果 |
|---|---|---|
| `num` | 访问整数值 | `10` |
| `&num` | `num` 的地址 | `0x1000` |
| `p` | `p` 保存的地址 | `0x1000` |
| `*p` | `p` 指向的整数值 | `10` |
| `&p` | `p` 自己的地址 | `0x2000` |

> **核心区分**：指针变量也是一个对象；“指针自己占多少字节”与“它指向的对象占多少字节”是两个问题。

## 三、32 位系统、64 位系统究竟是什么？

### 3.1 先认识“位（bit）”

- **1 bit**：一个二进制位，只能是 `0` 或 `1`。
- **1 Byte（字节）**：通常等于 **8 bit**。
- 32 bit = 4 Byte；64 bit = 8 Byte。

“32 位 / 64 位”常用来描述 CPU 架构、操作系统或**某个程序的运行模式**。它们有关联，但不是完全同一个概念。

### 3.2 对初学指针来说，最有用的是“程序的指针宽度”

在常见的 Windows x86 环境中：

| 程序类型 | 常见对象指针大小 | 直观理解 |
|---|---:|---|
| 32 位程序 | 4 字节（32 bit） | 用 32 位表示指针值 |
| 64 位 x86-64 程序 | 8 字节（64 bit） | 用 64 位表示指针值 |

**重要：64 位 Windows 可以运行 32 位程序。** 因此“电脑安装了 64 位 Windows”并不自动推出“所有程序的指针都是 8 字节”。还要看你编译出来的程序是 32 位还是 64 位。

例如你当前使用的 G++ 工具链目标是 `x86_64-w64-mingw32`，通常生成 64 位 Windows 程序，其普通对象指针一般占 8 字节。

> 不要把“64 位”直接理解为当前程序一定可以访问全部 `2^64` 字节内存；真实的虚拟地址空间还受 CPU、操作系统与进程限制。

### 3.3 怎么在自己的电脑上确认？

```cpp
#include <iostream>

int main() {
    std::cout << "sizeof(void*) = " << sizeof(void*) << " bytes\n";
    return 0;
}
```

在你目前的 64 位 G++ 环境中，通常得到：

```text
sizeof(void*) = 8 bytes
```

这查看的是**当前程序**中 `void*` 的大小，比只看 Windows 设置更直接。

## 四、`int*`、`double*`、`char*` 为什么通常一样大？

```cpp
int* pi = nullptr;
double* pd = nullptr;
char* pc = nullptr;
```

在你当前的 64 位 Windows + GCC 目标环境中，以上指针通常都是 **8 字节**。

| 类型 | 对象本身通常占用 | 指向这种对象的指针通常占用（当前 x64 环境） |
|---|---:|---:|
| `int` / `int*` | `int`：4 字节 | `int*`：8 字节 |
| `double` / `double*` | `double`：8 字节 | `double*`：8 字节 |
| `char` / `char*` | `char`：1 字节 | `char*`：8 字节 |
| `float` / `float*` | `float`：4 字节 | `float*`：8 字节 |

**为什么？** 指针保存的是内存地址；在同一种常见的 64 位对象地址模型中，地址表示宽度通常相同。`int*`、`double*` 的类型差别主要在于**它们所指向的对象类型**，而不是这里的指针字节数。

```cpp
int num = 10;
int* p = &num;

sizeof(p);   // 在当前 x64 环境中通常为 8
sizeof(*p);  // int 的大小，通常为 4
```

**不能据此推广成“C++ 标准保证所有种类的指针在任何平台上都占同样的字节数”。** 指针大小依赖具体平台和类型类别；这里讨论的是你当前常见的 64 位 Windows 对象指针。

### 用 Python 类比

```python
num = 10
```

Python 中名字与对象的关联通常由解释器管理，不需要你自己声明 `int*`。C++ 则显式区分了**被指向对象的类型**与**保存地址的指针类型**。Python 的 `id()` 也不应普遍等同于 C++ 的指针地址。

## 五、野指针：`int* p;` 没有初始化，会发生什么？

这是截图中最需要理解的安全问题。

```cpp
int main() {
    int* p;   // 声明了局部指针，但没有初始化
    // 现在不能安全地读取 p 或使用 *p
}
```

### 5.1 声明指针，不等于给它指定了目标

`int* p;` 表示声明一个可以保存 `int` 对象地址的指针变量。但这个**普通局部指针**没有被初始化，并不意味着它会自动指向某个有效的 `int`。

课程截图把它形容为“里面可能是垃圾地址，指向随机内存”，这有助于警惕风险，但**更准确地说**：此时 `p` 具有未初始化的、不确定的值；不能把它当成有效地址使用。读取未初始化指针值本身就可能导致未定义行为（具体规则依标准版本与情形有所差异），解引用更危险。

> **野指针（wild pointer）** 是常见的非正式说法，通常指没有经过正确初始化或指向无效对象的指针。不是说操作系统主动给它分配了一块随机有效的内存。

### 5.2 下面的代码千万不要运行来“测试一下”

```cpp
int* p;
*p = 10;  // 错误：p 没有被初始化为有效地址，行为未定义！
```

结果并不保证是某种固定报错，可能崩溃、破坏内存、表现异常，或者暂时看不出问题。**“能编译”不等于“能安全运行”。**

### 5.3 课件中的一句话需要修正

课件说“普通变量不会有‘野变量’的问题”，这个说法过于绝对：

```cpp
int a;   // 普通局部变量也可能未初始化
int* p;  // 普通局部指针也可能未初始化
```

**两者都要避免未初始化就使用。** 指针之所以格外危险，是因为错误地址参与的解引用可能影响不属于当前对象的内存。

## 六、空指针 `nullptr`：先明确“现在不指向任何对象”

推荐在尚未确定目标时这样初始化：

```cpp
int* p = nullptr;
```

`nullptr` 是 **C++11 引入的空指针字面量关键字**。它表示一个空指针值：目前不指向任何对象。

这时你可以安全地：

```cpp
if (p == nullptr) {
    std::cout << "p 目前为空指针\n";
}
```

但**绝对不能因为它是空指针就解引用**：

```cpp
int* p = nullptr;
*p = 10;  // 错误：解引用空指针，行为未定义！
```

### 6.1 野指针和空指针的对比

| 写法 | 初始状态 | 是否建议 | 能否马上使用 `*p` |
|---|---|---|---|
| `int* p;`（局部变量） | 未初始化、不确定 | 不建议 | ❌ |
| `int* p = nullptr;` | 确定为空指针 | ✅ 推荐的初始状态 | ❌ |
| `int num = 10; int* p = &num;` | 指向有效的 `num` | ✅ | ✅（`num` 生存期内） |

**关键结论**：空指针更安全，不是因为它能被随意访问，而是因为它的状态明确、可以检查，能避免不确定地址的误用。

### 6.2 `NULL` 与 `nullptr` 的区别

课件展示：

```cpp
int* p = NULL;
int* p = nullptr;
```

这是两种**分别独立书写时**用于初始化空指针的写法，不能在同一作用域内重复定义同一个 `p`。

- `NULL`：传统宏，常见实现为整数常量 `0`（细节由实现决定）；在 C++ 中有时可能造成重载歧义。
- `nullptr`：C++11 起提供的专用空指针字面量，类型为 `std::nullptr_t`，语义更加清楚。
- **现代 C++ 优先使用 `nullptr`**。

截图中“空指针也没有安全问题”应当理解为“初始化为空更利于安全地检查和管理”，并不是说可以对空指针执行 `*p`。

### 6.3 一个实用写法：先为空，之后再指向对象

```cpp
int num = 10;
int* p = nullptr;

// 某个时候确定了目标
p = &num;

if (p != nullptr) {
    std::cout << *p << '\n';  // 此时输出 10
}
```

检查是否非空只是基本条件，还需要确保被指向对象**仍然存在**，才能安全解引用。后面学习“悬空指针”时再深入这一点。

### 用 Python 理解 `nullptr`

```python
obj = None
```

它和 `int* p = nullptr` 在“暂时没有目标对象”的**意图**上相似，但 C++ 的指针是具有具体指向类型的地址型值，Python 中变量名绑定对象的模型并不相同。

## 七、延续上一节：内存地址为什么常用十六进制？

假设输出：

```text
0x7ff62a001000
```

- `0x`：表示后面采用**十六进制**显示。
- 十六进制使用 `0～9`、`A～F`，其中 `A=10`、`F=15`。
- 一位十六进制数等于 4 个二进制位；**两位十六进制数恰好表示 8 位（二进制），即 1 字节**。

例如：

```text
二进制：0001 1010
十六进制：0x1A
十进制：26
```

**内存地址并不是“用十六进制存储”的**。计算机内部使用二进制表示信息，开发工具通常用十六进制将地址显示给人看，方便阅读。

此外，指针的**数值表示**与它在内存中的**具体字节布局**不是同一回事；十六进制地址文本不意味着每个显示出来的十六进制数字都一定对应一段可访问的实际内存。

## 八、在你的 Windows + G++ 环境中运行实验

文件名建议：`pointer_02.cpp`

```cpp
#include <iostream>

int main() {
    int num = 10;

    int* p = nullptr;  // 安全地初始化为空指针

    std::cout << "sizeof(int)     = " << sizeof(int) << " bytes\n";
    std::cout << "sizeof(double)  = " << sizeof(double) << " bytes\n";
    std::cout << "sizeof(int*)    = " << sizeof(int*) << " bytes\n";
    std::cout << "sizeof(double*) = " << sizeof(double*) << " bytes\n";
    std::cout << "sizeof(char*)   = " << sizeof(char*) << " bytes\n";

    std::cout << "p is null? " << std::boolalpha << (p == nullptr) << '\n';

    p = &num;  // 将指针指向一个有效的 int 对象

    std::cout << "&num = " << &num << '\n';
    std::cout << "p    = " << p << '\n';
    std::cout << "&p   = " << &p << '\n';
    std::cout << "*p   = " << *p << '\n';

    *p = 20;
    std::cout << "num after *p=20: " << num << '\n';
    return 0;
}
```

编译运行（在文件所在目录打开 PowerShell）：

```powershell
g++ -std=c++17 -Wall -Wextra -Wpedantic -g -O0 .\pointer_02.cpp -o .\pointer_02.exe
.\pointer_02.exe
```

在当前常见的 x64 环境中，前五行一般是：

```text
sizeof(int)     = 4 bytes
sizeof(double)  = 8 bytes
sizeof(int*)    = 8 bytes
sizeof(double*) = 8 bytes
sizeof(char*)   = 8 bytes
```

后面会看到 `p is null? true`，随后 `&num` 与 `p` 的地址相同，`&p` 是另一个地址，最后 `num after *p=20: 20`。**具体地址数值无需一致。**

> 提醒：如果未来编写 `char*` 输出地址，直接 `std::cout << ptr` 可能被当作 C 风格字符串处理；要输出地址可转换为 `const void*`。这里使用 `int*` 避开了这个混淆。

## 九、最容易混淆的五件事

1. **64 位操作系统 ≠ 所有程序的指针都是 8 字节。** 要看实际编译的程序目标架构。
2. **`sizeof(p)` ≠ `sizeof(*p)`。** 前者是指针大小，后者是所指向类型的大小。
3. **`int* p;` ≠ `int* p = nullptr;`。** 前者（普通局部变量）未初始化，后者具有明确的空指针值。
4. **空指针可以检查，但不能解引用。** `*nullptr` 不是“修改一块空内存”。
5. **编译通过 ≠ 指针操作正确。** 使用无效指针可能出现未定义行为。

## 十一、本节总结与下一步

**记住这四句话就够了：**

- 指针变量存的是**地址**，而指针本身也有自己的类型和存储需求。
- 在你当前的 64 位 Windows G++ 程序里，常见对象指针通常占 **8 字节**，与其指向的是 `int` 还是 `double` 无关。
- **普通局部指针未初始化就使用很危险**；不知道指向哪里时先使用 `nullptr`。
- **`nullptr` 表示“不指向任何对象”**，可以比较检查，但不能解引用。
