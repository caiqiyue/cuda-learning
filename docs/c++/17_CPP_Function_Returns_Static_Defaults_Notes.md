## 0. 本节解决什么问题？

上一节研究的是**数据如何进入函数**：值传递复制数据，指针传参复制地址，引用传参让形参成为原对象的别名。现在研究的是**数据如何离开函数**，以及怎样方便地调用函数。

假设我们在函数内部计算出一个整数、创建一个数组，或者想获得已有对象的地址，函数执行结束以后，调用者还能否使用这些数据？为什么有的时候返回地址会出错，而有的时候可以？

本篇学习路线：

```text
普通值返回 → 指针返回 → 局部变量为何失效
                           ↓
              new 动态对象 / static 局部对象 / 外部对象
                           ↓
               返回数组与内存管理 → 更方便的容器返回
                           ↓
                  默认参数 → const string& 的含义
```

先建立一个核心问题意识：**返回的是什么（值还是地址）？如果返回的是地址，地址指向的对象在函数结束后是否还活着？**

# 第一部分：理解返回值与返回地址

## 1. 从最普通的返回值开始

### 1.1 函数返回一个整数

完整实验 1：

```cpp
#include <iostream>

int add(int a, int b)
{
    int sum = a + b;
    return sum;
}

int main()
{
    int result = add(3, 5);
    std::cout << result << '\n';
    return 0;
}
```

输出：

```text
8
```

逐步拆开：

- `int add(int a, int b)`：函数名是 `add`，形参是两个 `int`，返回值也是 `int`。
- `add(3, 5)`：调用函数，使用实参初始化形参 `a` 和 `b`。
- `int sum = a + b;`：在函数内部创建一个 `int` 对象，保存 8。
- `return sum;`：取得 `sum` 的值 8，将结果返回给调用者，然后退出函数。
- `int result = ...;`：调用者用返回的值初始化自己的 `result`。

### 1.2 `sum` 消失了，为什么 `result` 还在？

回忆已经学过的栈和局部变量。下面用教学地址表示两个不同对象（不是实际运行地址）：

```text
add() 正在执行：
    add 的局部对象            main 的运行上下文
    sum  [ 8 ] @0x1000       正在等待 add 的返回结果

return sum; 之后：
    add 的局部对象            main 的局部对象
    sum  生命周期结束        result [ 8 ] @0x2000
                          
          返回的是整数值 8，不是 0x1000
```

`sum` 与 `result` 是不同的对象。普通整数返回传递的是数值，调用者不依赖 `sum` 继续存在。实际上编译器可能使用寄存器传递这个整数，或者直接优化掉局部存储；上图只表达语言层面的对象关系。

因此，**返回局部变量的值是完全正常的，问题不是局部变量不能 return，而是不能把即将失效的局部对象当成可长期访问的对象返回给外部。**

Python 对照：

```python
def add(a, b):
    total = a + b
    return total

result = add(3, 5)
print(result)  # 8
```

结果一样，但 Python 返回的是对象的引用（语言层面是对象绑定），而 C++ 上面的 `int` 函数返回的是整数值。Python 运行时会管理返回对象的存活，不需要自己维持原局部名字 `total`。

## 2. 函数也可以返回指针

### 2.1 为什么需要返回地址？

假如调用者有两个整数 x 和 y，我们要找出哪一个比较大，并允许调用者继续修改那个整数。只返回最大值 30，调用者不能直接通过返回值修改原对象；如果返回该对象的地址，就能直接操作原来的整数。

先认识语法（`T` 代表具体对象类型）：

```cpp
T* function_name(/* 参数 */);  // 语法示意，不是完整程序
```

- `T*` 是函数的返回类型，表示返回一个指向 `T` 对象的指针。
- `int*` 不是返回一个 `int`，而是返回一个可用于访问 `int` 对象的指针值。
- `return &x;` 返回对象 `x` 的地址；如果 `p` 已经是指针，`return p;` 返回的是 `p` 保存的地址，不是指针变量 `p` 自身的地址。

### 2.2 先看一个安全的指针返回值

完整实验 2：

```cpp
#include <iostream>

int* find_larger(int* a, int* b)
{
    if (*a >= *b)
        return a;
    return b;
}

int main()
{
    int x = 10, y = 30;
    int* p = find_larger(&x, &y);
    std::cout << *p << '\n';
    std::cout << std::boolalpha << (p == &y) << '\n';
    *p = 99;
    std::cout << x << ' ' << y << '\n';
    return 0;
}
```

输出：

```text
30
true
10 99
```

这段函数要求传入两个有效的 `int` 地址。这里 `x` 与 `y` 都存在于 `main()`，所以满足要求。

假设 `&x = 0x1000`，`&y = 0x1004`：

```text
main: x [10] @0x1000       y [30] @0x1004
          ↑                    ↑
函数:   a [0x1000]          b [0x1004]
                               │
                     return b（返回 0x1004）
                               ↓
main:                      p [0x1004] ───► y [30]
```

形参 `a`、`b` 虽然会在返回时结束生命周期，但它们所指向的 `x`、`y` 不会随之结束。`p` 获取的是 `b` 保存的地址，而不是 `b` 这个局部指针的地址。通过 `*p = 99` 就能修改原来的 `y`。

这就是返回地址的价值：**不是创建一个新的整数结果，而是让调用者继续访问某个已有整数对象。**

# 第二部分：局部变量、内存与指针失效

## 3. 为什么不能返回普通局部变量的地址？

### 3.1 课件中的错误案例

下面故意展示错误写法，只用于分析，不要调用或解引用它的返回值：

```cpp
int* add_bad(int a, int b)
{
    int sum = a + b;
    return &sum;  // 错误：返回即将销毁的普通局部对象的地址
}
```

乍一看，`&sum` 的类型确实是 `int*`，与返回类型完全匹配。为什么还是错误？类型匹配只能说明返回表达式的类型合适，不能保证该地址在以后还有效。

### 3.2 串联上一节的内存知识

假设 `add_bad(3, 5)` 正在运行，`sum` 的教学地址为 `0x3000`。

```text
时间点 A：函数尚未返回
    add_bad 的栈帧（典型实现）
    ┌──────────────────┐
    │ a = 3, b = 5     │
    │ sum = 8          │  地址：0x3000
    └──────────────────┘
           return &sum

时间点 B：函数已经返回
    add_bad 的栈帧已结束 / 其空间可被后续调用复用
    0x3000 不再是一个活着的 sum 对象的地址

    任何仍指向原 sum 的指针都已经失效
```

`return &sum` 并不会把 `sum` 整个搬到 `main()`，也不会延长它的生命周期。`sum` 是普通局部变量，退出它所在的作用域后，对象生命周期结束。典型栈帧的存储可被重用。

释放或结束生命周期不代表原来那片内存一定立刻被填成 0，也不意味着你可以继续使用它。如果读取这种失效指针所指向的对象，属于**未定义行为（Undefined Behavior，UB）**：可能看似读出旧值，可能出现乱码、崩溃，也可能因为编译器优化表现完全不同。G++ 通常会警告 `address of local variable ... returned`，不要靠“运行一次没崩”判断程序正确。

> 图中“语法正确但无法正常返回结果”的实质是生命周期问题，不是所有返回指针的函数都无效。

### 3.3 三个已经学过的概念，现在联系起来

| 术语 | 具体含义 | 例子 |
|---|---|---|
| 作用域（scope） | 在源代码中某个名字可以被使用的范围 | `sum` 只能在其声明所在块的有效范围内直接使用 |
| 生命周期（lifetime） | 一个对象从创建到销毁的时间 | 普通局部 `sum` 退出块时结束 |
| 存储期（storage duration） | 语言规定存储持续的类别 | 自动存储期、静态存储期、动态存储期等 |

作用域是“哪里能通过名字访问”，生命周期是“对象是否还活着”；二者不一定相同。下一节的 `static` 就是典型例子。

课程截图把普通局部变量的释放称为“静态内存管理”。为了不跟即将学习的 `static` 混淆，本笔记采用标准术语：普通局部变量通常具有**自动存储期**；`static` 局部变量具有**静态存储期**。栈、堆和静态数据区是常见实现的内存组织方式，不等同于 C++ 语言关于存储期的定义。

### 3.4 Python 对照：为什么 Python 经常直接返回局部对象？

```python
def make_data():
    data = [1, 2, 3]
    return data

result = make_data()
print(result)  # [1, 2, 3]
```

Python 函数结束后，局部名字 `data` 不再有效，但是返回的列表通过 `result` 仍然可达，运行时会管理它的生命周期。C++ 的裸指针不会像 Python 的对象引用那样自动维持所指对象的生命周期。仅仅保留地址不保证对象仍然存在。

## 4. 第一种解决方法：使用 `new` 创建动态对象

如果只是求和，最简单且推荐的方式仍是 `int add(...)`，不需要指针，也不需要动态分配。但当业务确实要返回一个新创建的动态对象地址时，就要让这个对象独立于当前函数的局部作用域存在。

### 4.1 改造 `add` 函数

完整实验 3：

```cpp
#include <iostream>

int* add_heap(int a, int b)
{
    int* p = new int(a + b);
    return p;
}

int main()
{
    int* result = add_heap(3, 5);
    std::cout << *result << '\n';
    delete result;
    result = nullptr;
    return 0;
}
```

输出：`8`。

你之前已经问过 `int* p = new int;` 为什么有两部分存储。这里完全是同一个道理：

```text
函数正在运行（假设地址）：
    栈 / 自动存储期                       堆 / 动态存储期
    p [0x8000] @0x3000 ────────────────► int [8] @0x8000
       通常 8 字节                         通常 4 字节

return p; 后：
    局部 p 生命周期结束                  int [8] @0x8000 仍然存在
    main 的 result [0x8000] ────────────────────► ↑

调用者执行 delete result; 后：
    result 指针变量仍在，但原动态对象已释放
    result = nullptr; 使 result 不再保留旧地址
```

在当前 Windows x64 的常见实现中，局部指针通常 8 字节，`int` 通常 4 字节。`new` 动态申请的是 `int` 对象的存储，局部指针自己不是这次 `new` 申请的。实际分配器可能有管理开销。

### 4.2 为什么 `return p` 可以，`return &p` 却不行？

| 表达式 | 类型 | 教学例子中的含义 |
|---|---|---|
| `p` | `int*` | 动态整数的地址 `0x8000` |
| `*p` | `int` 左值 | 动态整数对象（读出为 8） |
| `&p` | `int**` | 局部指针变量自己的地址 `0x3000` |

`return p` 复制的是仍然有效的动态对象地址。`return &p` 首先类型就和 `int*` 不匹配；即使改成返回 `int**`，也仍然不能返回普通局部指针变量 `p` 自身的地址供外部使用，因为 `p` 随函数退出而销毁。

### 4.3 谁负责释放？

在这个接口约定里，`add_heap` 创建对象，调用者接管释放责任。所以必须在使用结束后执行 `delete result`，而不是在 `add_heap` 里面提前释放。

如果调用者不释放，且失去最后一个可用于释放的地址，就会发生内存泄漏。也不要把同一个动态对象释放两次。多个指针保存同一地址不代表多个独立对象；将其中一个置空也不会自动清除其他指针。

原始 `new/delete` 是理解内存机制的重要练习，但实际现代 C++ 中，独占管理动态对象通常会优先使用之前学过的 `std::unique_ptr`（末尾提供选读示例）。

# 第三部分：static 关键字与局部静态变量

## 5. 为什么需要 `static`？

假如一个函数需要记录自己被调用了多少次。你可能先写一个普通局部变量 `count`。每一次函数调用都会重新创建它，所以它无法记住上一次的结果。

完整实验 4：

```cpp
#include <iostream>

void normal_count()
{
    int count = 0;
    ++count;
    std::cout << count << ' ';
}

void static_count()
{
    static int count = 0;
    ++count;
    std::cout << count << ' ';
}

int main()
{
    normal_count(); normal_count(); normal_count();
    std::cout << '\n';
    static_count(); static_count(); static_count();
    std::cout << '\n';
    return 0;
}
```

输出：

```text
1 1 1
1 2 3
```

为什么第二个函数记得上一次的值？因为 `static int count = 0;` 声明的是局部静态变量，它不会在每次函数退出时销毁。它进入静态存储期，初始化只发生一次（常量初始化或零初始化可能在进入函数之前完成；需要动态初始化时，在控制流第一次到达该声明时执行）。以后每次调用都会使用同一个已经存在的对象。

| 调用次数 | 普通 count | static count |
|---|---|---|
| 第一次 | 重新初始化为 0，++ 后为 1 | 初始为 0，++ 后为 1 |
| 第二次 | 新对象从 0 开始，得到 1 | 使用上次的 1，得到 2 |
| 第三次 | 新对象从 0 开始，得到 1 | 使用上次的 2，得到 3 |

注意：`static` 不等于 `const`。`static` 在这里改变的是存储期，`const` 才限制修改。`++count` 可以正常执行。

### 5.1 作用域和生命周期终于分开了

```cpp
void f()
{
    static int count = 0;
    ++count;
}
```

- `count` 的名字依然只在 `f` 中的相应范围可见，`main()` 不能直接写 `count` 访问它。
- 但 `count` 对象不会因为 `f()` 返回而销毁；其存储在程序执行期间持续存在。在正常程序终止时，已经完成初始化的局部静态类对象会进行相应的析构。
- 典型实现会把局部静态对象放在静态数据区域，而非每次调用都重新分配的栈帧中。

示意（区域仅为概念图，并非操作系统固定地址布局）：

```text
调用 f 第一次           调用 f 第二次          调用 f 第三次
[本次函数栈帧]         [新的函数栈帧]         [新的函数栈帧]
        │                     │                    │
        └─────────────────────┴────────────────────┘
                      同一个 static count
                     [ 1 → 2 → 3 ]（静态存储期）
```

Python 可以用外部变量保存调用状态，例如：

```python
count = 0

def count_calls():
    global count
    count += 1
    return count
```

效果类似，但 Python 的全局变量在模块范围可见，C++ 的函数内 `static` 保持局部名字的可见性，二者并不完全等价。

## 6. 第二种解决方法：返回 `static` 局部变量地址

现在再来看课程中的 `add` 例子：

完整实验 5：

```cpp
#include <iostream>

int* add_static(int a, int b)
{
    static int sum = 0;
    sum = a + b;
    return &sum;
}

int main()
{
    int* p1 = add_static(3, 5);
    std::cout << *p1 << '\n';

    int* p2 = add_static(10, 20);
    std::cout << std::boolalpha << (p1 == p2) << '\n';
    std::cout << *p1 << ' ' << *p2 << '\n';
    return 0;
}
```

输出：

```text
8
true
30 30
```

### 6.1 为什么 `p1` 最后也变成了 30？

注意，这里变的是 `*p1` 读出的数据，而不是 `p1` 保存的地址。

```text
第一次调用 add_static(3,5)：
    p1 [0x9000] ───► static sum [8] @0x9000

第二次调用 add_static(10,20)：
    p1 [0x9000] ───┐
                   ├──► static sum [30] @0x9000
    p2 [0x9000] ───┘
```

`static int sum = 0;` 只初始化一次，但下一行 `sum = a + b;` 仍会在每次调用时执行。两个指针指向同一个 `sum` 对象，所以第二次计算的结果覆盖了第一次。

如果你写成 `static int sum = a + b;` 并去掉后续赋值，那么初始化通常在第一次调用时执行，后续调用就不会随新的 a、b 自动更新 sum。这与 `static int sum = 0; sum = a + b;` 有本质区别。

### 6.2 什么时候使用 static？

适合：让函数记住调用次数、保存需要跨调用存在的状态，或提供生命周期足够长的共享只读常量（例如固定查找表）。

不适合：希望每次调用都得到互相独立、可长期保存的结果时。多线程同时修改同一个静态对象还可能产生数据竞争（暂时无需学习具体同步机制）。

**不要对指向局部静态对象的指针调用 `delete`。** 该对象不是由 `new` 创建的，其存储由语言规定的生命周期管理。对 `add_static` 的返回值调用 `delete` 是未定义行为。

补充：截图提到 `static` 还能修饰函数。它在命名空间级普通函数上通常表示内部链接（可先理解为该函数只供当前翻译单元内部使用）；类中的 `static` 成员又有其他含义。这里先掌握局部静态变量，不要把这些用途混为一谈。

## 7. 第三种解决方法：返回原本就存在的对象地址

除了 `new` 和 `static`，还有一类非常常见的做法：返回调用者提供的对象地址（第 2 节正是如此）。也可以返回全局对象的地址：

```cpp
int global_value = 100;

int* get_global()
{
    return &global_value;
}
```

全局对象通常具有静态存储期，因此函数返回后仍然存在。调用者不应 `delete` 它。过多使用可修改全局数据容易使函数之间形成隐蔽依赖，所以不必为了返回地址而把所有局部变量改成全局变量。

把几种方法比较一下：

| 来源 | 函数退出后目标是否还存在 | 调用者是否 delete |
|---|---|---|
| 普通局部 `int sum` | 否 | 不可以，不能继续使用返回地址 |
| `new int(...)` | 是，直到被释放 | 按接口约定接管所有权时需要 |
| 局部 `static int sum` | 是，正常使用期间 | 不可以 |
| 全局 `int` | 是，正常使用期间 | 不可以 |
| 调用者传进来的对象 | 只要调用者对象仍然有效就可以 | 不能仅因为函数返回了地址就 delete |

**能否返回地址，首先看目标对象生命周期；是否要 delete，再看对象如何创建、谁拥有释放责任。**

# 第四部分：函数如何返回数组？

## 8. 先回顾数组和指针的关系

```cpp
int arr[3] = {1, 2, 3};
int* p = arr;
```

这里有两个不同对象：`arr` 是一个实际包含 3 个 `int` 的数组；`p` 是一个指针变量，保存第一个元素的地址。数组名不是独立存储地址的指针变量。

假设 `int` 是 4 字节，`arr` 从 `0x4000` 开始：

```text
数组 arr（12 字节）
地址     0x4000    0x4004    0x4008
         ┌───────┬───────┬───────┐
         │   1   │   2   │   3   │
         └───────┴───────┴───────┘
          ↑         ↑        ↑
        arr[0]    arr[1]   arr[2]
          ↑
 p [0x4000]（是另一个对象，通常 8 字节）
```

在 `int* p = arr;` 中，数组表达式 `arr` 转换成首元素地址。这是上一节解释为什么普通数组形参 `int arr[]` 实际接收一个指针的基础。

现在如果返回类型是 `int*`，写 `return arr;` 也会发生这样的转换：函数返回首元素地址，而不是把三个元素一起作为一个原生数组返回。

C++ 不允许函数直接按值返回内置数组类型（如 `int[3]`）。但这不代表 C++ 不能返回一组数据：可以返回指针、让调用者提供数组，也可以使用 `std::array` 或 `std::vector`，后面会分别讲解。

## 9. 课程中的四种返回数组方式

### 9.1 错误方式：返回普通局部数组的首地址

```cpp
int* make_bad_array()
{
    int arr[3] = {1, 2, 3};
    return arr;  // 错误：返回即将失效的局部数组首地址
}
```

数组 `arr` 拥有三个局部 `int` 元素，函数退出时这些对象不再存在。即使调用者接收到了原来数组首地址，也不允许通过它读取任何元素。

这与第 3 节的 `return &sum;` 完全一样：一个返回普通局部整数的地址，另一个返回普通局部数组第一个整数的地址。不要运行这段错误代码来寻找所谓“正确输出”。

### 9.2 可行方式一：局部 static 数组

完整实验 6：

```cpp
#include <iostream>

int* get_static_array()
{
    static int arr[3] = {1, 2, 3};
    return arr;
}

int main()
{
    int* p = get_static_array();
    for (int i = 0; i < 3; ++i)
        std::cout << p[i] << ' ';
    std::cout << '\n';

    p[0] = 99;
    int* q = get_static_array();
    std::cout << q[0] << '\n';
    std::cout << std::boolalpha << (p == q) << '\n';
    return 0;
}
```

输出：

```text
1 2 3 
99
true
```

因为 `arr` 只有一份，函数退出后仍然存在，`p` 和 `q` 都指向它。`static` 初始化只发生一次，再调用时不会自动恢复为 `{1, 2, 3}`。

```text
p ──┐
    ├──► static arr [99][2][3]
q ──┘
```

这种方式适合生命周期很长的共享数据。若只想提供只读数据，可以使用 `static const int arr[3] = {1, 2, 3};`，并把函数返回类型改为 `const int*`。不能 `delete[] p`，因为数组不是通过 `new[]` 创建的。

### 9.3 可行方式二：动态数组 `new[]`

完整实验 7：

```cpp
#include <iostream>

int* make_array()
{
    int* arr = new int[3]{1, 2, 3};
    return arr;
}

int main()
{
    int* p = make_array();
    int* q = make_array();
    p[0] = 99;

    std::cout << p[0] << ' ' << q[0] << '\n';
    std::cout << std::boolalpha << (p == q) << '\n';

    delete[] p;
    delete[] q;
    p = nullptr;
    q = nullptr;
    return 0;
}
```

输出：

```text
99 1
false
```

这一次，每次调用都动态创建一个新的数组，所以得到两个互相独立的数组，修改其中一个不会影响另一个。局部指针 `arr` 结束生命周期不会释放它所指向的数组。

```text
第一次调用：p ───► 堆中数组 A [99][2][3]
第二次调用：q ───► 堆中数组 B [ 1][2][3]
```

调用者接管这两个数组的所有权，应分别执行 `delete[]`。`new int[3]` 必须配套 `delete[]`，不能用单对象的 `delete`。

注意：所谓动态数组不是指创建后可以直接扩容的原生数组。`new int[3]` 创建的数组仍固定为 3 个元素；动态指的是存储在运行时分配、生命周期不依赖当前函数的结束。此前学习的扩容操作实际上是重新创建一个更大的数组并复制数据。

### 9.4 可行方式三：已有全局数组

```cpp
int global_arr[3] = {1, 2, 3};

int* get_global_array()
{
    return global_arr;
}
```

全局数组不依赖 `get_global_array()` 的局部作用域，因此可以返回它的首元素地址。跟 `static` 数组相似，多次调用得到的指针指向同一个数组，也不能 `delete[]`。区别是，全局数组的名字在其相应的命名空间范围内可见；局部静态数组的名字只在所在函数块内可见。

### 9.5 四种方式对比

| 返回地址来源 | 返回后仍有效？ | 多次调用的数组是否独立？ | 谁释放 |
|---|---|---|---|
| 普通局部 `int arr[3]` | 否 | 不适用 | 自动；不能使用返回的地址 |
| `static int arr[3]` | 是 | 否，同一数组 | 自动，不得 delete[] |
| `new int[3]` | 是，直到释放 | 是，每次新建 | 本例调用者 delete[] |
| 全局 `int arr[3]` | 是 | 否，同一数组 | 自动，不得 delete[] |

## 10. 一个新问题：只返回首地址，怎么知道数组长度？

假设 `int* p = make_array();`。虽然可以通过 `p[0]`、`p[1]`、`p[2]` 访问元素，但是 `p` 本身不记录数组的元素个数。

```cpp
sizeof(p);       // 指针变量的大小，常见 x64 下为 8
sizeof(*p);      // 一个 int 的大小，常见环境下为 4
```

因此，不能通过 `sizeof(p) / sizeof(*p)` 计算动态数组有多少元素。这里的 8 / 4 = 2 与实际的数组长度 3 完全无关。这也正是上一节关于数组传参和 `sizeof` 的知识在返回值场景中的应用。

既然返回 `int*` 不携带长度，该怎么办？最简单的办法是由接口约定固定长度；如果长度可变，则把长度同时提供给调用者，或通过结构体、容器一起管理地址和长度。

完整实验 8（根据调用者指定的长度分配数据）：

```cpp
#include <iostream>
#include <cstddef>

int* make_zeros(std::size_t n)
{
    return new int[n]{};   // 所有元素初始化为 0
}

int main()
{
    std::size_t n = 5;
    int* p = make_zeros(n);
    for (std::size_t i = 0; i < n; ++i)
        std::cout << p[i] << ' ';
    std::cout << '\n';
    delete[] p;
    return 0;
}
```

输出：`0 0 0 0 0`。`std::size_t` 是适合表示对象大小和元素数量的无符号整数类型。这里调用者自己知道 n，无需从指针推断长度。

额外注意：`new int[n]` 中的整数元素没有确定初始值；`new int[n]{}` 则会将其初始化为 0。裸指针索引不做自动边界检查，必须保证访问索引在 `[0, n)` 内。

## 11. 更常见的做法：调用者提供数组，函数负责填充

截图推荐在函数外创建数组，再传进去修改。理解了前几节就很容易明白原因：数组由调用者管理，函数不必为返回的地址安排额外的生命周期。

完整实验 9：

```cpp
#include <iostream>
#include <cstddef>

void fill_array(int* arr, std::size_t n)
{
    for (std::size_t i = 0; i < n; ++i)
        arr[i] = static_cast<int>(i + 1);
}

int main()
{
    int data[5]{};
    std::size_t n = sizeof(data) / sizeof(data[0]);
    fill_array(data, n);
    for (std::size_t i = 0; i < n; ++i)
        std::cout << data[i] << ' ';
    std::cout << '\n';
    return 0;
}
```

输出：`1 2 3 4 5`。

`static_cast<int>` 是明确告诉编译器将当前数值转换成 `int`；这里 n 固定为 5，转换安全。本例主要是理解指针和长度传参，而不是学习类型转换。

逐步看：

```text
main() 先创建数组：data [0][0][0][0][0]
                         ↑
fill_array 的 arr ────────┘   n = 5

函数直接修改同一数组：data [1][2][3][4][5]

函数退出：arr 和 n 两个形参结束生命周期
          main 中的 data 仍然有效
```

函数没有返回值（`void`），但并不代表它不能产生结果：结果通过修改调用者提供的数组写了回去。这就是上一节的指针传参发挥作用的地方。

使用约定：调用者保证 `arr` 指向至少 n 个可以写入的整数；函数在 n 个元素范围内处理。原始指针不会验证容量。`data` 是普通局部数组，因此不需要、也不能对它执行 `delete[]`。

为什么工程中经常用这一模式？例如计算函数可以接受输入缓冲区与输出缓冲区，由上层提前分配数据，避免每次调用反复申请内存。对于大模型推理、量化或反量化操作，这是一个常见的接口思路（这里并不声称某个具体框架接口就是这样实现的）。

## 12. 现代 C++ 补充：其实可以直接返回一组数据

截图中的“不推荐函数返回数组”，主要针对返回裸指针指向内置数组的形式。不能把它理解成所有 C++ 函数都不应该返回数组数据。

对于你有 Python 背景这一点，下面两个例子会更熟悉。

Python：

```python
def make_data():
    return [1, 2, 3]
```

C++：

完整实验 10：

```cpp
#include <iostream>
#include <array>
#include <vector>

std::array<int, 3> make_fixed()
{
    return {1, 2, 3};
}

std::vector<int> make_dynamic()
{
    return {1, 2, 3, 4};
}

int main()
{
    auto a = make_fixed();
    auto b = make_dynamic();
    b.push_back(5);
    std::cout << a.size() << ' ' << a[0] << '\n';
    std::cout << b.size() << ' ' << b[4] << '\n';
    return 0;
}
```

输出：

```text
3 1
5 5
```

先认识三点即可：

- `std::array<int, 3>` 是一个包含 3 个整数的固定长度容器对象，可以按值返回；`a.size()` 返回元素数。
- `std::vector<int>` 是可以管理动态元素存储的容器对象，支持 `push_back()` 增加元素，并自动管理资源；你目前可以类比 Python 的 list，不过它的元素类型固定为 int。
- `auto` 让编译器根据初始化表达式推断变量类型，不代表变成了 Python 的动态类型。

这里返回的是容器对象，而不是普通局部数组的失效地址。C++ 的值返回语义及复制省略、移动等机制使其安全，并且通常不需要我们额外写手动复制或释放代码。具体如何减少复制是后面学习对象时的内容，本节不深挖。

| 需求 | 可以优先考虑 |
|---|---|
| 返回一个计算出来的整数 | `int` 按值返回 |
| 返回多个固定数量的值 | `std::array` 或 `struct` 按值返回 |
| 返回长度在运行时确定的一组数据 | `std::vector` 按值返回 |
| 在已有的底层缓冲区内写数据 | 指针 + 长度，或引用/容器引用 |
| 返回某个已有元素的地址 | 指针，注意目标生命周期 |

# 第五部分：函数参数的默认值

## 13. 什么是默认参数？为什么需要它？

当一个参数在大部分调用中使用相同配置，只有少数时候需要改动，就可以为这个参数指定默认值。调用者不传参数时，编译器按函数声明中给出的默认值补上；明确传入时，就使用实际参数。

先从最简单的整数开始，而不是直接写 `const std::string&`。

完整实验 11：

```cpp
#include <iostream>

int add(int a, int b = 10)
{
    return a + b;
}

int main()
{
    std::cout << add(3) << '\n';
    std::cout << add(3, 5) << '\n';
    return 0;
}
```

输出：

```text
13
8
```

理解调用过程：`add(3)` 在这个调用点相当于 `add(3, 10)`；`add(3, 5)` 显式传入 b，因此默认值 10 不使用。这里 `a` 没有默认值，所以 `add()` 不合法。

默认参数不会改变函数形参类型，也不会创建另一个只有一个参数的重载函数；`add` 本身仍然是接收两个整数的函数，只是调用处允许省略尾部有默认值的实参。

Python 对照：

```python
def add(a, b=10):
    return a + b

print(add(3))     # 13
print(add(3, 5))  # 8
```

用法非常相近。至于 C++ 默认实参从函数声明取得、表达式按需在调用时求值，与 Python 默认值通常在定义函数时求值一次的区别，知道即可，不要把两个语言的机制完全等同。

## 14. 多个默认参数：为什么只能从右边省略？

```cpp
void configure(int threads, int batch = 32, bool verbose = false);
```

| 调用方式 | 相当于传入什么 |
|---|---|
| `configure(4)` | 4、32、false |
| `configure(4, 64)` | 4、64、false |
| `configure(4, 64, true)` | 4、64、true |
| `configure()` | 不合法，threads 必填 |

对于目前学习的普通函数声明，某一个参数提供默认值后，其右边的参数也都必须有可用默认值。

错误例子：

```cpp
void f(int a = 1, int b);  // 错误：此处假设 b 没有其他可见默认声明
```

正确例子：

```cpp
void f(int a, int b = 1);
void g(int a = 1, int b = 2);
```

假设只想改 verbose，不能这样做：`configure(4, , true)`。因为 C++ 普通函数的调用使用位置匹配，不支持留空中间参数，也没有 Python 那样的 `configure(4, verbose=True)` 关键字传参。你需要写 `configure(4, 32, true)`。

## 15. 回到截图：`const std::string& msg = "..."` 到底是什么意思？

课程里是这样的函数：`void say_hello(const std::string& msg = "周杰伦")`。它一次用了三个已学概念：字符串、引用和 `const`，再增加一个默认参数。逐层拆开就不难了。

### 15.1 第一步：普通字符串值传递

```cpp
void say_hello(std::string msg)
{
    std::cout << "Hi I am: " << msg << '\n';
}
```

如果把一个已有 `std::string` 对象传进来，按值传递会用它初始化一个独立的形参对象。函数内部对 msg 的赋值不改变外部那个字符串。对于大对象，如果只需要读取而不需要复制，这种方式可能有额外开销。

### 15.2 第二步：引用传参

```cpp
void change_name(std::string& msg)
{
    msg = "New name";
}
```

`std::string&` 是一个已有字符串对象的别名，函数可以直接读取或修改原对象。它不需要额外复制整份字符串。但普通非 const 左值引用通常不能绑定字符串字面量转换产生的临时 `std::string` 对象。

### 15.3 第三步：添加 const，表示只读访问

```cpp
void say_hello(const std::string& msg)
{
    std::cout << "Hi I am: " << msg << '\n';
    // msg = "Other";  // 错误：不能通过这个 const 引用修改字符串
}
```

`const std::string&` 不会复制已有字符串对象，可以读取原数据，但不能通过该引用修改它。引用并不拥有独立的字符串副本；原始非 const 对象仍可由它的拥有者修改。

为什么不写 `const std::string msg`？它仍然是按值传递，只是函数内部不能修改那份形参对象。加上 `&` 才意味着引用传递。

### 15.4 第四步：加入默认值

完整实验 12（为了避免 Windows 终端中文编码影响，用英文名字替代课件里的中文例子）：

```cpp
#include <iostream>
#include <string>

void say_hello(const std::string& msg = "Jay")
{
    std::cout << "Hi I am: " << msg << '\n';
}

int main()
{
    say_hello();
    say_hello("JJ");
    std::string name = "Tom";
    say_hello(name);
    return 0;
}
```

输出：

```text
Hi I am: Jay
Hi I am: JJ
Hi I am: Tom
```

可以按如下方式拆分声明：

| 部分 | 含义 |
|---|---|
| `void` | 函数无返回值 |
| `say_hello` | 函数名 |
| `std::string` | 数据类型 |
| `&` | 引用传参 |
| `const` | 不允许通过这个引用修改数据 |
| `msg` | 形参的名称 |
| `= "Jay"` | 没有传入实参时的默认表达式 |

`"Jay"` 本身是字符串字面量（C 风格的字符数组），这里会转换成一个临时 `std::string` 对象，`const std::string&` 可以绑定该对象。临时对象在这次函数调用期间有效，调用完成所在的完整表达式结束时销毁。对于 `say_hello(name)`，则直接绑定已有的字符串对象，不需要复制一份完整的字符串。

```text
say_hello(name)  : msg（只读别名） ──► main 中已有的 name 对象
say_hello()      : msg（只读别名） ──► 本次调用用到的临时 string("Jay")
```

只要函数在调用过程中使用 msg，比如输出它，就没有问题；但不能随意把指向临时对象的引用或地址保存到外部供后续调用使用，因为对象可能已经销毁。这和本节前面学习的生命周期是同一条原则。

## 16. 函数声明和定义分开时，默认值写在哪里？

上一节已经学习过函数声明用来让调用者提前知道函数的名称、参数和返回类型。我们可以先声明函数，稍后再提供完整代码。

完整实验 13：

```cpp
#include <iostream>

int add(int a, int b = 10);  // 声明：提供默认参数

int main()
{
    std::cout << add(3) << '\n';
    std::cout << add(3, 5) << '\n';
    return 0;
}

int add(int a, int b)        // 定义：不再重复默认值
{
    return a + b;
}
```

输出为 13、8（各占一行）。当编译器处理 `main()` 中的调用时，已经看见了上面的函数声明，所以知道省略的 b 应该使用 10。

不要在同一作用域的声明和后续定义中重复指定同一个参数的默认值（即使两个默认值相同）。工程中函数声明经常写在 `.h` / `.hpp` 文件，定义写在 `.cpp` 文件。一般把默认实参放在供调用者看到的头文件声明中，实现部分只写类型和参数名。如果没有单独的前置声明，并且直接在调用之前定义函数，可以像第 13 节那样把默认参数写在定义里。

## 17. 用已学的智能指针返回动态对象

回顾第 13 篇笔记：`std::unique_ptr` 用于独占管理动态对象，离开作用域时自动执行相应释放操作。第 4 节的 `add_heap` 需要调用者显式 `delete`，如果函数确实需要把一个动态对象交给外部，可以直接返回智能指针来表达管理责任的转移。

完整实验 14：

```cpp
#include <iostream>
#include <memory>

std::unique_ptr<int> make_number(int value)
{
    return std::make_unique<int>(value);
}

int main()
{
    auto p = make_number(8);
    std::cout << *p << '\n';
    return 0;  // p 自动销毁并释放所管理的 int
}
```

输出：`8`。这里 `p` 推断出的类型是 `std::unique_ptr<int>`，而不是裸指针 `int*`。如果必须创建动态数组，也有 `std::unique_ptr<int[]>`，不过日常管理动态数组一般优先考虑 `std::vector`。

**注意**：只是计算一个整数时，直接返回 `int` 就够了。本例不是建议把所有返回值都包装成智能指针，而是说明动态对象所有权可以随返回值交给调用者。

## 18. 引用也可以作为返回值吗？

上一节学过引用是原对象的别名。如果希望返回某个仍然存在的对象，使调用者直接使用这个别名，也可以声明 `int&` 返回值。

完整实验 15：

```cpp
#include <iostream>

int& choose_larger(int& a, int& b)
{
    if (a >= b)
        return a;
    return b;
}

int main()
{
    int x = 10, y = 30;
    int& r = choose_larger(x, y);
    r = 99;
    std::cout << x << ' ' << y << '\n';
    return 0;
}
```

输出：`10 99`。

返回的引用是 `y` 的别名，而 `y` 由 `main()` 创建，仍然存在。与返回指针一样，**不能返回普通局部对象的引用供函数结束后使用**。引用不自动延长普通对象的生命周期，也可能成为悬空引用。这里先理解这个限制即可，引用返回的更多细节留到后续课程。

# 第七部分：总结与练习

## 19. 易错点速查

| 容易误解的说法 | 应该怎样理解 |
|---|---|
| 局部变量不能 return | 普通局部对象的值可以安全返回；其失效地址或引用不能用于后续访问 |
| return 指针会移动被指向对象 | 返回裸指针只传递指针值，不会移动或复制目标对象 |
| 局部指针销毁会释放堆对象 | 裸指针与动态对象的生命周期独立；必须有明确释放机制 |
| 函数返回的指针都应该 delete | 只对符合 new 分配要求且由自己负责释放的对象操作 |
| static 对象每次调用都会重新初始化 | 初始化只发生一次；后续普通赋值仍可改变数据 |
| static 就是 const | static 与存储期等有关，const 限制修改 |
| 返回数组就是返回完整数组内容 | 裸指针返回通常只提供首元素地址，不携带长度 |
| C++ 不适合返回数组数据 | 内置数组不能直接按值返回，但标准容器可以 |
| 默认参数可以随便留空 | 普通位置调用只能省略末尾有默认值的参数 |
| const std::string& 总要创建副本 | 已有 string 对象可以直接绑定；字面量转换时可能产生临时 string |

## 20. 判断输出：先自己推演，再看解析

### 练习 1：值返回

```cpp
int f()
{
    int x = 10;
    return x;
}
// 在 main 中调用：int result = f();
```

问：f 结束以后，result 是多少？是否安全？

<details><summary>答案</summary>

result 为 10，完全安全。返回整数值而非 x 的地址，result 是调用者自己的整数对象。

</details>

### 练习 2：返回动态对象地址

```cpp
int* f()
{
    int* p = new int(10);
    return p;
}
// 在 main 中调用：int* q = f();
```

问：函数结束后 p 和 `new int(10)` 创建的对象分别发生什么？q 还能读取 10 吗？

<details><summary>答案</summary>

局部指针 p 生命周期结束，动态对象仍然存在；q 保存了该对象的有效地址，可以读取 10。使用结束需要 `delete q;`（本例中约定 q 接管释放责任）。

</details>

### 练习 3：static 多次调用

```cpp
int* f(int x)
{
    static int result = 0;
    result = x;
    return &result;
}
// 在 main 中：
// int* p = f(10);
// int* q = f(20);
```

问：调用后 `*p`、`*q` 和 `p == q` 分别是什么？

<details><summary>答案</summary>

20、20、true。只存在一个静态 result 对象，第二次调用覆盖了第一次的值。p、q 都记录该对象的地址。不能 delete 这两个指针指向的静态对象。

</details>

### 练习 4：数组和 sizeof

```cpp
int* f()
{
    return new int[5]{1, 2, 3, 4, 5};
}
// 在 main 中：int* p = f();
```

问：典型 Windows x64 环境下 sizeof(p)、sizeof(*p) 分别是多少？能计算出数组长度 5 吗？

<details><summary>答案</summary>

通常为 8、4 字节。二者相除得到 2，并不是数组长度；函数需要用接口约定或其他方式提供实际长度。这个数组通过 new[] 创建，应使用 delete[] p 释放。

</details>

### 练习 5：默认参数

```cpp
int f(int a, int b = 10, int c = 100)
{
    return a + b + c;
}
```

问：`f(1)`、`f(1, 2)`、`f(1, 2, 3)` 结果是什么？`f()` 是否合法？

<details><summary>答案</summary>

111、103、6。f() 不合法，因为 a 没有默认值。

</details>

### 练习 6：综合选择

阅读下面四种需求，为它们挑选合适的返回方式：

1. 计算两个整数的和。
2. 返回调用者数组中某个元素的位置，供调用者修改。
3. 返回一个运行时长度才能确定的整数序列。
4. 提供一个永远不需要修改的固定查找表（假设返回地址，且表由函数持有）。

<details><summary>答案</summary>

1. `int` 按值返回。
2. `int*` 指向已有元素（该元素必须仍然存在），或者返回索引；若保证有有效元素也可以用引用。
3. 优先 `std::vector<int>` 按值返回。
4. 可以让函数持有 `static const` 数组，并返回 `const int*`；同时明确长度。或者按需求使用标准容器。

</details>

## 22. 本节最后要形成的知识链

```text
函数返回什么？
  ├─ 返回值：调用者得到结果，不依赖被返回的普通局部整数继续存在
  ├─ 返回指针：调用者得到地址，必须检查目标对象的生命周期
  │    ├─ 普通局部对象：返回后已失效
  │    ├─ static / 全局对象：跨调用存在，不要 delete
  │    ├─ new 创建的对象：明确释放责任
  │    └─ 调用者已有对象：只要它仍有效，就可以继续访问
  └─ 返回一组数据：可使用标准容器，或让调用者提供缓冲区

函数如何方便地调用？
  └─ 默认参数：不传就使用默认值；显式传参则覆盖默认值
```

本节最核心的不是记住 `int* add(...)` 或 `static int` 的写法，而是建立这三个判断习惯：**函数返回的是什么？返回后所依赖的对象是否仍然有效？如果涉及动态资源，谁负责释放？**

掌握这些知识以后，再学习函数重载、更多引用用法、函数模板和 C++ 工程接口，会更容易看懂这些接口为何这样设计。
