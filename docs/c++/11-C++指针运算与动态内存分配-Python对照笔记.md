## 1. 复习：指针保存地址，解引用访问对象

```cpp
int num = 10;
int* p = &num;

std::cout << num << '\n';   // 10：直接访问 num
std::cout << p << '\n';     // num 的地址（示例形式：0x...）
std::cout << *p << '\n';    // 10：经地址读取 num
```

| 写法 | 含义 |
|---|---|
| `int* p` | 声明一个“指向 `int` 的指针变量” |
| `&num` | 取得 `num` 的地址 |
| `p` | 指针变量保存的地址 |
| `*p` | 解引用：访问 `p` 所指向的 `int` 对象 |
| `&p` | 指针变量 `p` 自己的地址 |

**关键区分**：`p` 本身保存的是一个地址；`*p` 是该地址所对应的对象。对 `p` 和对 `*p` 赋值，效果截然不同：

```cpp
int a = 10, b = 20;
int* p = &a;

*p = 11;  // 修改 a 的值，a 变为 11
p = &b;   // 修改指向，p 现在保存 b 的地址
```

### 与 Python 的对照

Python 的 `b = a` 通常表示名字 `b` 绑定到 `a` 所引用的对象；C++ 的 `int* p = &a` 则让一个**具有指针类型的对象 `p`**保存 `a` 的地址。两者都能帮助理解“间接访问”，但它们不是同一种语言机制。

## 2. 指针加减：为什么 `p + 1` 不是地址加 1 字节？

截图中的核心例子是：

```cpp
int num = 10;
int* p = &num;
std::cout << p << '\n';
++p;
std::cout << p << '\n';
```

如果 `sizeof(int) == 4`，打印出来的地址数字通常相差 4。但这里**不能因此继续对 `p` 解引用**：因为它最初指向的是一个单独的 `int`，`++p` 最多得到该对象的“尾后位置”（one-past），这个位置不是一个可读写的 `int` 对象。

### 2.1 规则：指针每加减 1，移动一个元素的大小

假设内存地址以字节编址：

| 指针类型 | 常见 `sizeof(所指向类型)` | 在有效数组范围内 `p + 1` 的地址步长 |
|---|---:|---:|
| `char*` | 1 字节 | 1 字节 |
| `int*` | 4 字节 | 4 字节 |
| `double*` | 8 字节 | 8 字节 |

在有效数组范围内，可建立这样的直觉：

\[
\text{地址}(p+n)=\text{地址}(p)+n\times \operatorname{sizeof}(T)
\]

其中 `T` 是 `p` 所指向的对象类型。**这是理解地址步长的模型，不是允许对任意地址做加减的许可证**。指针算术必须遵守所指对象所属数组的边界规则。

### 2.2 更准确的实验：使用数组，而非单个变量

```cpp
#include <iostream>

int main() {
    int values[5] = {10, 20, 30, 40, 50};
    int* p = values; // 指向第 0 个元素

    std::cout << "sizeof(int) = " << sizeof(int) << '\n';
    std::cout << "p     = " << p << '\n';
    std::cout << "p + 1 = " << p + 1 << '\n';
    std::cout << "p + 2 = " << p + 2 << '\n';
    std::cout << "*(p + 2) = " << *(p + 2) << '\n'; // 30
}
```

假设第 0 个元素的地址是 `0x1000`，并且 `int` 占 4 字节：

```text
地址（示意）  0x1000  0x1004  0x1008  0x100C  0x1010
元素           10      20      30      40      50
下标           [0]     [1]     [2]     [3]     [4]
               ^
               p

p + 1 -> 0x1004 -> values[1]
p + 2 -> 0x1008 -> values[2]
```

### 2.3 边界：允许形成“尾后指针”，但不能解引用

```cpp
int a[3] = {1, 2, 3};
int* first = a;
int* end = a + 3;    // 可以形成尾后指针
// *end;              // 错！不能解引用尾后指针
// a + 4;             // 错！超出同一数组允许的指针算术范围
```

**截图纠偏**：如果 `double* p2 = &num2;` 且 `num2` 是单个 `double`，再执行 `p2 += 4` 并不是一个合规的数组访问实验；不要仅凭地址被打印出来就认为它安全。想演示 `p2 += 4`，应让 `p2` 指向至少 5 个 `double` 的数组。

## 3. 指针与数组：`*(p + i)` 为什么等价于 `p[i]`？

截图中的第二个核心示例是：

```cpp
int v[] = {1, 2, 3, 4, 5};
int* vp = v;

std::cout << *vp << '\n';       // 1
std::cout << *(vp + 1) << '\n'; // 2
std::cout << vp[1] << '\n';     // 2
```

在这里 `vp` 指向数组首元素，`vp + 1` 指向第二个元素。C++ 的下标运算定义使得：

```cpp
vp[i] == *(vp + i)  // 对有效的数组元素访问，两种表达式表示同一元素
```

| 数组下标 | 指针形式 | 得到的值 |
|---|---|---:|
| `v[0]` | `*vp` 或 `*(vp + 0)` | 1 |
| `v[1]` | `*(vp + 1)` | 2 |
| `v[2]` | `*(vp + 2)` | 3 |

还可以通过指针修改数组里的元素：

```cpp
*(vp + 2) = 33;
std::cout << v[2] << '\n';  // 33
```

因为 `v[2]` 和 `*(vp + 2)` 访问的是**同一个元素**，不是两份数据。

### 3.1 数组名不是指针变量

```cpp
int v[5] = {1, 2, 3, 4, 5};
int* vp = v;
```

- `v` 的类型是“包含 5 个 `int` 的数组”；在很多表达式中，它会转换成指向首元素的指针。
- `vp` 的类型才是真正的 `int*` 指针变量，可以改成指向其他有效的 `int` 对象。
- `sizeof(v)` 得到整个数组占用的字节数；`sizeof(vp)` 得到**指针变量**的字节数，两者不同。

```cpp
std::cout << sizeof(v) << '\n';  // 常见 20（5 × 4）
std::cout << sizeof(vp) << '\n'; // Windows x64 常见 8
```

### 3.2 与 Python 的对照

Python：

```python
v = [1, 2, 3, 4, 5]
print(v[2])  # 3
v[2] = 33
```

C++：

```cpp
int v[] = {1, 2, 3, 4, 5};
std::cout << v[2] << '\n';
v[2] = 33;
```

两者都能用下标访问元素；重要区别是：**Python 的 `list` 有边界检查且长度可变化，而 C++ 原生数组长度固定，`v[越界下标]` 没有自动边界检查，可能触发未定义行为。**

## 4. 为什么需要动态内存分配？

课程截图对比了：

```cpp
int num = 10;
int nums[] = {1, 2, 3, 4, 5};
```

与动态分配：

```cpp
int* p = new int(10);
int* nums = new int[5];
```

### 4.1 先理解“对象的生存期”

对于**函数中的普通局部变量**：

```cpp
void work() {
    int num = 10;
    int nums[5] = {1, 2, 3, 4, 5};
} // 到达作用域末尾时，二者生存期结束
```

这些对象通常具有**自动存储期**（可以先通俗理解为常见的“栈上局部变量”），作用域结束时就自动结束生存期。它们**不是一定占用内存直到程序终止**。

对于 `new` 创建的对象：

```cpp
int* p = new int(10);
// ... 使用 *p
// 在适当时机：delete p;
```

对象具有**动态存储期**，通常不会因为创建它的函数作用域结束就自动释放；必须由相应的资源管理机制负责释放，否则可能发生内存泄漏。

**核心区别不是“有没有在运行时占据内存”**——两者都可能占据内存，而是**存储期、生存期以及由谁负责管理资源**。

### 4.2 为什么动态数组有用？

比如数组长度需要由用户输入决定，或数据较大、不适合放在普通局部数组中。在 C++17 中，原生数组通常要求编译期已知其长度，而动态分配可以在运行时确定长度：

```cpp
int n = 5;
int* arr = new int[n]{};  // 申请 n 个 int，{} 使元素值初始化为 0
// ...
delete[] arr;
```

**注意**：`new[]` 申请出来的数组**仍然是固定长度**，不能对它直接进行“扩容”操作；若需要更大空间，必须重新分配并搬移／复制数据。现代 C++ 则优先采用 `std::vector`。

## 5. `new` 与 `delete`：申请与释放要配对

课程截图列出的基础语法：

| 用途 | 申请 | 释放 |
|---|---|---|
| 单个对象 | `new T` | `delete p` |
| 数组 | `new T[n]` | `delete[] p` |

### 5.1 单个整数对象

```cpp
#include <iostream>

int main() {
    int* p = new int(10); // 动态创建并初始化为 10
    std::cout << *p << '\n';
    delete p;             // 释放该动态对象
    p = nullptr;          // 防止后续误用这个指针变量
}
```

`new int(10)` 会动态创建一个 `int` 对象并返回指向它的指针，`delete p` 结束相应对象的生存期并释放存储空间。

### 5.2 数组

```cpp
#include <iostream>

int main() {
    int* p = new int[5]{}; // 5 个元素均初始化为 0
    p[0] = 1;
    p[1] = 2;
    *(p + 2) = 3;          // 等价于 p[2] = 3

    std::cout << p[0] << ' ' << p[1] << ' ' << p[2] << '\n';

    delete[] p;           // 释放整组动态数组对象
    p = nullptr;
}
```

### 5.3 三个必须避免的错误

```cpp
// 错误 1：只声明指针，未初始化就解引用
int* p;
// *p = 10;  // 未定义行为

// 错误 2：new[] 和 delete 搭配错误
int* q = new int[5];
// delete q; // 错！应该 delete[] q;
delete[] q;

// 错误 3：释放后继续访问（悬空指针）
int* r = new int(42);
delete r;
// std::cout << *r; // 错！已释放对象不再存在
r = nullptr;
```

额外注意：

- `new int;` 申请的整数对象**不会自动初始化为 0**；`new int{}` 或 `new int(0)` 才明确初始化为 0。
- `delete` 后把某个指针变量设为 `nullptr` 只能避免继续误用这个变量，**无法自动修复其他同样指向已释放对象的指针**。
- 申请和释放不匹配、重复 `delete`、解引用已释放对象，都会造成严重问题。
- 发生异常时，手写 `new` / `delete` 容易遗漏释放，因此现代 C++ 推荐 RAII：`std::vector`、`std::unique_ptr` 等。

### 5.4 截图里的“静态／动态内存管理”如何正确理解？

课程把传统变量和数组统称为“静态内存管理”，是为了与 `new` 的手动管理形成对比。严格来说，C++ **静态存储期**是另一种专门的概念；普通函数局部变量一般是**自动存储期**，不要混为一谈。

同时，`int* p = new double;` 的类型不匹配，正确示例应为 `double* p = new double{};`，或者 `int* p = new int{};`。

## 6. `new[]` 创建的数组，为什么不能直接插入或删除元素？

```cpp
int* p = new int[5]{10, 20, 30, 40, 50};
```

这块分配的数组有 5 个位置，假设是：

```text
下标:   0    1    2    3    4
数据:  [10] [20] [30] [40] [50]
```

如果希望在下标 `2` 插入 `99`，结果应变成 6 个元素：

```text
下标:   0    1    2    3    4    5
数据:  [10] [20] [99] [30] [40] [50]
```

原数组只有 5 个元素的空间，所以不能直接写 `p[5] = ...` 来扩容。正确思路是截图中介绍的：

1. 申请一块长度为 6 的新数组；
2. 按顺序复制旧元素，在指定位置插入新元素；
3. 释放旧数组 `delete[]`；
4. 将持有者指针改为新数组地址，并更新长度。

### 6.1 手动实现：在指定下标插入一个元素

下面是练习 `new[]` 的完整、可编译示例，**只适合学习底层机制**：

```cpp
#include <iostream>

int main() {
    int n = 5;
    int* data = new int[n]{10, 20, 30, 40, 50};
    const int pos = 2;
    const int value = 99;

    int* bigger = new int[n + 1];
    for (int i = 0; i < pos; ++i) {
        bigger[i] = data[i];
    }
    bigger[pos] = value;
    for (int i = pos; i < n; ++i) {
        bigger[i + 1] = data[i];
    }

    delete[] data;  // 释放旧数组
    data = bigger;  // 指针改指向新数组
    ++n;            // 逻辑长度更新为 6

    for (int i = 0; i < n; ++i) {
        std::cout << data[i] << ' ';
    }
    std::cout << '\n'; // 10 20 99 30 40 50

    delete[] data;
    data = nullptr;
}
```

这里 `data = bigger` 改变的是**指针的指向**，并不是把旧数组本身变大。这正好衔接你之前学过的 `const char* s = "abc"; s = "xyz";`：都是指针变量更新地址，但动态数组还涉及所有权与释放。

### 6.2 手动实现：删除某个位置的元素

原始数组：

```text
[10] [20] [30] [40] [50]
```

删除下标 `2` 的 `30`，期望：

```text
[10] [20] [40] [50]
```

核心思路：

```cpp
// 假设 data 指向合法的 n 元素动态数组；n > 0；0 <= pos < n
int* smaller = new int[n - 1];
for (int i = 0; i < n - 1; ++i) {
    smaller[i] = (i < pos) ? data[i] : data[i + 1];
}
delete[] data;
data = smaller;
--n;
```

这段是**核心操作片段**，须在正确的上下文中使用，并最终 `delete[] data`。在生产代码里建议使用 `std::vector`，不必自行承担所有权与异常安全问题。

### Python 对照

Python `list` 可以直接：

```python
x = [10, 20, 30, 40, 50]
x.insert(2, 99)
x.pop(3)
```

它不意味着底层完全没有重新分配和搬移数据，而是这些细节由 Python 的列表实现帮你处理了。

## 7. 现代 C++ 更推荐 `std::vector`

图片强调了：原生数组和 `new[]` 动态数组没有直接“插入、删除、扩容”的高级接口。**标准库 `std::vector` 提供了这些能力**。

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v = {10, 20, 30, 40, 50};

    v.insert(v.begin() + 2, 99); // 在下标 2 插入 99
    v.erase(v.begin() + 3);      // 删除下标 3 的元素
    v.push_back(60);             // 末尾追加 60

    for (int x : v) {
        std::cout << x << ' ';
    }
    std::cout << '\n';
}
```

输出：

```text
10 20 99 40 50 60
```

| 能力 | Python `list` | C++ 原生数组 | C++ `std::vector` |
|---|---|---|---|
| 按下标访问 | `a[i]` | `a[i]` | `a[i]` |
| 自动管理元素存储 | 是 | 固定长度 | 是 |
| 追加元素 | `append` | 不提供 | `push_back` |
| 指定位置插入 | `insert` | 需自行设计新数组方案 | `insert` |
| 删除元素 | `pop` / `del` | 需自行设计新数组方案 | `erase` |
| 访问越界检查 | 有 | `[]` 无 | `[]` 无；可用 `.at()` |

**关于内存**：`std::vector` 的元素通常存放在连续内存中，容量不足时可能重新分配；此时指向原有元素的指针／引用／迭代器可能失效。这点以后学到引用与迭代器时再深入。

> 学习路线建议：**理解原生数组与指针 → 会读 `new` / `delete` → 了解内存所有权 → 日常优先使用 `std::vector` 和 RAII。** 无须把裸 `new[]` 当作常规开发方式。

## 8. 一个完整实验：指针算术 + 动态数组 + vector

本例适合保存在 `first-class/pointer_dynamic.cpp`，并用你当前的 G++ 编译：

```cpp
#include <iostream>
#include <vector>

int main() {
    // A. 指针与数组
    int a[] = {1, 2, 3, 4, 5};
    int* p = a;
    std::cout << "A: " << *p << ", " << *(p + 1) << '\n';
    *(p + 2) = 33;
    std::cout << "A after: " << a[2] << '\n';

    // B. 动态数组
    int* data = new int[3]{10, 20, 30};
    std::cout << "B: ";
    for (int i = 0; i < 3; ++i) {
        std::cout << data[i] << ' ';
    }
    std::cout << '\n';
    delete[] data;
    data = nullptr;

    // C. vector 插入与删除
    std::vector<int> v = {10, 20, 30};
    v.insert(v.begin() + 1, 99); // 10 99 20 30
    v.erase(v.begin() + 2);      // 10 99 30
    std::cout << "C: ";
    for (int x : v) {
        std::cout << x << ' ';
    }
    std::cout << '\n';
}
```

在 Windows PowerShell：

```powershell
g++ -std=c++17 -Wall -Wextra -g -O0 .\pointer_dynamic.cpp -o .\pointer_dynamic.exe
.\pointer_dynamic.exe
```

预期：

```text
A: 1, 2
A after: 33
B: 10 20 30
C: 10 99 30
```

### 8.1 为什么这里不拿单个 `int` 做 `p += 4` 演示？

因为我们希望演示的每一次移动、解引用都指向**同一个真实数组中的有效元素**，而不是“生成了一个看起来像地址的数值就以为可访问”。正确的 C++ 内存操作首先要保证对象存在，地址合法，边界有效。

## 9. 与未来 llama.cpp / 量化代码的联系

你以后会看到这样的数据：

```cpp
float* scales;           // 指向浮点数数据
std::uint8_t* packed;    // 指向打包后的 8-bit 字节数据（需包含 <cstdint>）
```

在**指向有效数组**的情况下：

- `scales + 1`：跨过一个 `float` 元素；常见 4 字节；
- `packed + 1`：跨过一个 `std::uint8_t` 元素；8 位字节机器上常见 1 字节；
- `packed[i]`：读取原始字节；
- 解读 Q4/NVFP4 时，还需要根据格式定义做**位运算、Scale 与 Block 索引映射**。

这里请重点建立这样的关系：

> **指针步长由 C++ 指向的存储类型决定，而量化数值格式（NVFP4、Q4 等）决定这些字节如何被解释。**

暂时无需深入量化 Kernel；先会判断“指针指向什么类型、对象有多少个、访问是否合法”。

## 10. 常见误区速查

| 常见说法 | 更准确的理解 |
|---|---|
| “`int* p` 是 8 字节，所以 `p + 1` 加 8” | 错。步长通常是 `sizeof(int)`；指针**自身大小**与指向对象的大小是两回事。 |
| “打印出来的新地址存在，就可以访问” | 错。指针值的表示形式不能证明对象存在，也不能证明解引用合法。 |
| “数组名就是存储首地址的指针变量” | 不准确。原生数组是数组对象，其名字在许多表达式中会转换为首元素指针。 |
| “函数中的变量会一直占内存到程序结束” | 不准确。普通局部变量一般在作用域结束时结束生存期。 |
| “`new[]` 是动态数组，所以能自动变长” | 错。`new[]` 只允许运行时确定初始长度；改变长度仍需重新分配。 |
| “只要 `delete p` 就能释放 `new int[5]`” | 错。`new[]` 必须用 `delete[]`。 |
| “手动 `new` / `delete` 是现代 C++ 的推荐默认写法” | 错。应理解底层原理，但优先使用 `std::vector` / RAII。 |
| “`nullptr` 为空，就可以 `*p`” | 错。空指针不可解引用。 |
| “`delete` 之后写 `p = nullptr`，就没有悬空指针问题了” | 只能让这**一个**指针变量不再悬空；其他别名仍可能悬空。 |

## 11. 自测题（建议先独立思考）

**问题 1**：以下代码中假设 `sizeof(int) == 4`，`p + 2` 与 `p` 的地址通常差多少字节？

```cpp
int a[5] = {10, 20, 30, 40, 50};
int* p = a;
```

**问题 2**：`p[3]` 等价于什么指针表达式？

**问题 3**：`int x = 10; int* p = &x;` 后，`*(p + 1)` 是否能够安全读取下一个整数？为什么？

**问题 4**：这段代码中的释放语句是否正确？

```cpp
int* data = new int[100];
delete data;
```

**问题 5**：你想从 5 个数的动态数组中删除第 3 个数，为什么不能只对 `delete[] data` 进行操作？

**问题 6**：Python 的 `list.insert()` 最接近 C++ 标准库中哪个容器的哪个操作？

<details>
<summary>参考答案（做完再展开）</summary>

1. 通常差 8 字节（2 × 4），前提是指针运算发生在同一数组的允许范围内。
2. `*(p + 3)`。
3. 不能。单个 `int` 可以视为大小为 1 的数组进行有限指针算术，`p + 1` 至多是尾后指针，不能解引用。
4. 错误，应写 `delete[] data;`。

## 12. 本节知识总结

- **指针加减不是按“地址加 1 字节”理解，而是按所指元素大小前进或后退。**
- **指针算术只能在同一个数组的允许范围内进行；尾后位置不可解引用。**
- `v[i]` 与 `*(v + i)` 在合法数组访问时可以表示同一个元素。
- 普通局部变量一般由作用域管理生存期；`new` 创建的对象需要正确管理和释放。
- `new` 配 `delete`，`new[]` 配 `delete[]`。
- 动态分配数组不等于自动扩容；插入和删除往往需要额外分配与复制。
- **真正写日常 C++ 时，优先使用 `std::vector`；学习 `new` / `delete` 是为了理解底层机制、阅读已有代码和排查资源问题。**
