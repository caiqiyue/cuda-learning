# C++ 函数进阶：`<span>inline</span>`、函数重载与函数匹配

本节围绕三个问题展开：

1. `<span>inline</span>` 是什么意思，和宏有什么区别？
2. 为什么可以存在多个同名函数？
3. 调用同名函数时，编译器如何选择？

## 一、内联函数 `<span>inline</span>`

### 1. 基本写法

在函数定义前加上 `<span>inline</span>`：

```
inline int add(int a, int b)
{
    return a + b;
}
```

它仍然是一个正常函数，有参数类型、返回值和作用域，也进行类型检查。

### 2. 什么是“内联展开”？

普通函数调用通常涉及传递参数、跳转、返回等操作。对于很小且频繁调用的函数，编译器可能直接把函数逻辑放到调用处。

例如：

```
int result = add(10, 20);
```

优化后，可以近似理解为：

```
int result = 10 + 20;
```

这种优化叫作**内联展开**。

但要修正图片中的一个简化说法：

> 写了 `<span>inline</span>` 不保证展开；没有写 `<span>inline</span>` 的函数，也可能被编译器展开。

是否展开由编译器决定。展开也不保证一定更快，过度展开可能增加程序体积。

### 3. `<span>inline</span>` 与多文件编程

现代 C++ 中，`<span>inline</span>` 的一个重要用途是：**允许函数定义放在头文件中，被多个源文件包含**。

例如 `<span>math_utils.h</span>`：

```
#ifndef MATH_UTILS_H
#define MATH_UTILS_H

inline int add(int a, int b)
{
    return a + b;
}

#endif
```

多个 `<span>.cpp</span>` 都可以包含：

```
#include "math_utils.h"
```

对于这里的普通外部链接函数，只要各处定义满足一致性等规则，就不会因为多个源文件包含而产生重复定义问题。

注意：

* 头文件保护防止同一个编译单元重复包含。
* `<span>inline</span>` 允许符合规则的定义出现在多个编译单元。
* 两者解决的问题不同。

初学阶段可以记为：

```
普通函数：头文件放声明，cpp 放实现
inline 函数：通常把完整定义放在头文件
```

## 二、图片中的字符串比较函数

```
#include <string>

inline const std::string& longer_string(
    const std::string& first,
    const std::string& second
)
{
    return first.size() > second.size() ? first : second;
}
```

### 为什么参数是 `<span>const std::string&</span>`？

需要比较字符串长度，不需要修改字符串：

* `<span>&</span>`：引用传递，避免复制字符串。
* `<span>const</span>`：不能通过这个参数修改字符串。

### 为什么返回 `<span>const std::string&</span>`？

返回的是两个已有字符串中的一个：

* 返回引用，避免复制字符串。
* 返回 `<span>const</span>` 引用，不允许调用者通过结果修改字符串。
* 长度相同时，按这里的表达式返回 `<span>second</span>`。

```
std::string a = "hello";
std::string b = "C++";

const std::string& result = longer_string(a, b);
```

`<span>result</span>` 引用的是 `<span>a</span>`，没有创建新的字符串副本。

### 返回引用的生命周期

函数返回后，原字符串必须仍然存在。

不要这样保存结果：

```
const std::string& result = longer_string(
    std::string("hello"),
    std::string("C++")
);
```

两个临时字符串在这条语句结束时销毁，`<span>result</span>` 随后成为悬空引用。

不想管理这种生命周期关系时，可以让函数按值返回：

```
std::string longer_string(
    const std::string& first,
    const std::string& second
)
{
    return first.size() > second.size() ? first : second;
}
```

## 三、内联函数与宏

### 1. 宏进行预处理替换

```
#define SQUARE(x) ((x) * (x))
```

调用：

```
int result = SQUARE(2 + 3);
```

展开后近似为：

```
int result = ((2 + 3) * (2 + 3));
```

宏不是函数，不具备函数参数的类型检查和正常调用语义。

### 2. 函数具有正常的参数语义

```
inline int square(int x)
{
    return x * x;
}
```

调用：

```
int result = square(2 + 3);
```

先计算实参，再用结果初始化形参。

即使宏添加了括号，也仍然可能重复计算实参：

```
int x = 3;
int result = SQUARE(++x); // 展开后重复修改 x，存在未定义行为
```

函数则不同：

```
int x = 3;
int result = square(++x); // x 变为 4，result 为 16
```


| 对比                 | 宏               | `<span>inline</span>`函数        |
| -------------------- | ---------------- | -------------------------------- |
| 处理方式             | 预处理替换       | 正常函数编译                     |
| 参数类型检查         | 无函数级类型检查 | 有                               |
| 实参是否可能重复求值 | 可能             | 不因函数体多次使用形参而重复求值 |
| 是否支持重载         | 不支持函数重载   | 支持                             |
| 是否保证调用处展开   | 宏进行替换       | 不保证内联展开                   |

通常优先使用函数实现计算逻辑，用 `<span>const</span>`、`<span>constexpr</span>` 表示常量；宏仍常用于条件编译和头文件保护。

补充：现代 C 语言从 C99 起也有 `<span>inline</span>`，不能简单认为它只存在于 C++。

## 四、函数重载

### 1. 什么是重载？

在同一作用域内，可以声明多个同名函数，只要参数列表能够区分。

```
int add(int a, int b)
{
    return a + b;
}

double add(double a, double b)
{
    return a + b;
}

int add(int a, int b, int c)
{
    return a + b + c;
}
```

调用：

```
add(1, 2);       // int, int
add(1.5, 2.5);   // double, double
add(1, 2, 3);    // 三个 int
```

设计用意是：

> 功能相近时使用同一个名称，通过参数表达不同的使用方式。

### 2. 哪些差异可以形成重载？

**参数数量不同：**

```
void print(int value);
void print(int first, int second);
```

**参数类型不同：**

```
void print(int value);
void print(double value);
```

**参数类型顺序不同：**

```
void show(int count, double value);
void show(double value, int count);
```

### 3. 哪些差异不能形成重载？

**只有参数名称不同：**

```
void print(int x);
void print(int y); // 同一个函数的再次声明
```

**只有返回类型不同：**

```
int get_value();
double get_value(); // 错误：不能只靠返回类型区分
```

**只有默认参数不同：**

```
void print(int value);
void print(int value = 10); // 仍然是同一个函数
```

默认参数不属于区分重载的依据。`<span>main</span>` 也不能重载。

## 五、`<span>const</span>` 与函数重载

判断关键是：

> `<span>const</span>` 修饰的是按值传递的参数本身，还是通过指针、引用访问的对象？

### 1. 按值参数的顶层 `<span>const</span>` 不能区分重载

```
void process(int value);
void process(const int value);
```

这两条声明表示同一个函数。

因为函数拿到的是独立副本，形参是否可以修改，不改变调用者能传入什么类型。

但在函数定义内部，`<span>const</span>` 仍然有效：

```
void process(const int value)
{
    // value = 20; // 错误
}
```

指针本身的 `<span>const</span>` 也一样：

```
void process(int* p);
void process(int* const p); // 同一个函数
```

第二种写法只限制函数内部不能改变指针副本的指向。

### 2. 指向对象的 `<span>const</span>` 可以区分重载

```
void process(int* p);
void process(const int* p);
```

这是两个函数：

* `<span>int*</span>`：可以通过指针修改对象。
* `<span>const int*</span>`：不能通过指针修改对象。

```
int a = 10;
const int b = 20;

process(&a); // 优先选择 int*
process(&b); // 选择 const int*
```

### 3. 引用对象的 `<span>const</span>` 可以区分重载

```
void process(int& value);
void process(const int& value);
```

```
int a = 10;
const int b = 20;

process(a);  // int&
process(b);  // const int&
process(30); // const int& 可以绑定临时值
```

汇总：


| 参数形式                                       | 能否靠此差异形成重载 |
| ---------------------------------------------- | -------------------- |
| `<span>int</span>`与`<span>const int</span>`   | 不能                 |
| `<span>int*</span>`与`<span>int* const</span>` | 不能                 |
| `<span>int*</span>`与`<span>const int*</span>` | 能                   |
| `<span>int&</span>`与`<span>const int&</span>` | 能                   |

## 六、编译器如何选择重载函数？

这个过程叫作**重载决议**，可以先分成三步理解：

```
找到候选函数
    ↓
筛选可行函数
    ↓
选择最佳匹配
```

考虑下面的声明：

```
void f();
void f(int x);
void f(int x, int y);
void f(double x, double y = 1.5);
```

调用：

```
f(3.14);
```

### 1. 候选函数

找到调用处可以查找到的同名函数。

本例中，四个 `<span>f</span>` 都是候选函数。

### 2. 可行函数

检查：

* 实参数量是否满足要求，考虑默认参数。
* 实参能否合法转换为对应形参类型。


| 函数                                   | 是否可行 | 原因                                              |
| -------------------------------------- | -------- | ------------------------------------------------- |
| `<span>f()</span>`                     | 否       | 不能接收一个实参                                  |
| `<span>f(int)</span>`                  | 是       | `<span>double</span>`可以转换成`<span>int</span>` |
| `<span>f(int, int)</span>`             | 否       | 缺少一个实参                                      |
| `<span>f(double, double = 1.5)</span>` | 是       | 第二个参数可以使用默认值                          |

### 3. 最佳匹配

`<span>3.14</span>` 是 `<span>double</span>`：

```
f(int);                   // 需要 double -> int
f(double, double = 1.5);   // 第一个参数精确匹配
```

因此选择：

```
f(double, double = 1.5);
```

等价于本次调用：

```
f(3.14, 1.5);
```

注意：默认参数使函数成为可行函数，但“使用默认参数更少”本身不是优先规则。

## 七、类型转换的匹配优先级

对于本节涉及的基础类型，可以先记住：

```
精确匹配 > 类型提升 > 一般类型转换
```

### 精确匹配

```
void print(int);
void print(double);

print(10);   // int
print(3.14); // double
```

### 类型提升优于一般转换

```
void print(int);
void print(double);

short value = 10;
print(value); // 选择 int
```

这里：

* `<span>short -> int</span>` 属于整型提升。
* `<span>short -> double</span>` 属于一般数值转换。

不能简单按“哪个类型占字节更接近”来判断。

## 八、多参数匹配与二义性

### 1. 逐个比较参数

```
void f(int x, int y);
void f(double x, double y);
```

调用：

```
f(10, 20);     // 两个参数都精确匹配 int
f(1.5, 2.5);   // 两个参数都精确匹配 double
```

### 2. 两边各有优势时可能产生二义性

```
f(10, 3.14); // 编译错误：二义性
```


| 候选函数                         | 第一个参数`<span>10</span>` | 第二个参数`<span>3.14</span>` |
| -------------------------------- | --------------------------- | ----------------------------- |
| `<span>f(int, int)</span>`       | 精确匹配                    | 需要转换                      |
| `<span>f(double, double)</span>` | 需要转换                    | 精确匹配                      |

两个函数各有一个参数更好，没有唯一的最佳匹配。

基础判断原则是：

> 最佳函数需要在每个实参的匹配上都不比其他候选差，并且至少有一个更好。

可以明确表达意图：

```
f(10.0, 3.14); // 选择 double 版本
f(10, 3);      // 选择 int 版本
```

### 3. 默认参数也可能造成二义性

```
void show(int value);
void show(int value, int count = 1);

show(10); // 错误：两个函数都能精确匹配
```

编译器不会因为第一个函数“不需要默认参数”就优先选择它。

## 九、重载与作用域

内层声明的同名函数，可能隐藏外层函数，而不是自动与它们组成重载集合。

```
void print(int value);

void demo()
{
    void print(double value);

    print(10); // 找到内层 print(double)，int 转换成 double
}
```

查找在内层发现 `<span>print</span>` 后，外层的 `<span>print(int)</span>` 被隐藏。

可以显式指定全局作用域：

```
::print(10); // 调用全局 print(int)
```

因此要分清：

```
重载：在可参与选择的同名函数中比较参数
隐藏：名称查找时，外层同名声明被遮住
```

## 十、联系学生案例

```
Student* find_top_student(
    const std::vector<Student*>& students
);

Student* find_top_student(
    const std::vector<std::unique_ptr<Student>>& students
);
```

两个函数功能相同，参数类型不同，因此构成重载：

```
std::vector<Student*> first;
std::vector<std::unique_ptr<Student>> second;

find_top_student(first);  // 普通指针容器版本
find_top_student(second); // 智能指针容器版本
```

编译器根据传入容器的类型选择函数，不根据返回值选择。

## 本节总结


| 知识点                                   | 核心理解                                             |
| ---------------------------------------- | ---------------------------------------------------- |
| `<span>inline</span>`                    | 不保证展开；允许符合规则的函数定义出现在多个编译单元 |
| 内联优化                                 | 编译器将函数逻辑放到调用处                           |
| 宏                                       | 预处理替换，不是普通函数                             |
| 函数重载                                 | 同名函数通过不同参数列表区分                         |
| 顶层`<span>const</span>`                 | 不能单独区分按值参数的重载                           |
| 指针、引用指向对象的`<span>const</span>` | 可以区分重载                                         |
| 函数匹配                                 | 候选函数 -> 可行函数 -> 最佳匹配                     |
| 二义性                                   | 没有唯一最佳函数，编译报错                           |
| 作用域                                   | 先决定能查找到哪些函数，再进行重载选择               |
